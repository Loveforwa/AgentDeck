AgentDeck MVP 实施计划

把设计画布里的需求拆成可以交给一个 agent 独立完成的任务，按“地基 → 白板和终端 → 工作区和 Git → 状态和网页”的顺序推进。M3 做完就是基础 MVP：能用它过完一整天真实的开发。MVP 分版本做：M0–M4 是 MVP v1；2026-10-24 第一轮验收后加了 MVP v2（M5）和 MVP v3（M6），需求在设计画布“MVP v2 · v3”那一页（画板 11、12），v2 的分波安排见下面“MVP v2 实施安排”。2026-10-25 加了插件（M7）：Auto-approve、token 用量这类以后别人也能写的功能，需求在设计画布“插件能力”那一页（画板 PL0–PL3）。2026-10-27 加了Agent 集群（M8）：按模板组一队 agent 做复杂任务，AgentDeck 里的调度器排活、守规矩，你只在关卡上出现，需求在设计画布“Agent 集群”那一页（画板 C0–C5）。2026-10-28 定了 9 点 harness 的改动：M8 加自由模式（No template）、agentdeck 命令行和 Lead 记进度（CR10–CR21），M7 加 Auto-resume（PL4–PL9），新开 Session（M9）、Agent 接入加固（M10）、Skill 管理（M11）、远程（M12），需求在设计画布“Session”“Agent 接入”“Skill 管理”“手机 · 远程”四页和“Agent 集群”页的 C6–C9。

  8. M710 项

    插件

    右键终端（或工作区框）的菜单里有一组插件项，是所有插件的入口。第一批只做两个：Auto-approve（终端底边左侧的红色小书签）和 Usage 用量记录（贴在终端上方或下方的细长条，我们自己读各 agent 的记录）。画板 12 的 N3、N4 并到这里。2026-10-28 加 Auto-resume（PL4–PL9）：被额度打断的任务恢复后先接着做，再发 Prompt queue 排着的；按“agent + 配置目录”算账号，同一账号的一起停、恢复后每 30 秒续一个；额度的识别、归组、错开发送只在主进程的 LimitService 里写一份，插件和 CR8 共用。需求见“插件能力”页，规则见 docs/plugins.md（插件手册）。

    完成标准右键终端能开关 Auto-approve 并看到红色书签，claude、codex、omp、pi 都能自动批准；右键终端打开 Usage，终端旁边出现用量条，能拖到上方或下方；codex 被额度打断后恢复时自己接着做，claude 自己续跑时不重复发、排着的提示词在它续完后发（TC-78、TC-79）。

  9. M822 项

    Agent 集群

    你选一个模板、写一句目标，AgentDeck 组一队 agent：总设计拆任务、定接口，几个实现者各在自己的 worktree 里并行做，换一家来审，合进集群分支。排活、开窗口、跑检查、守分工、等额度都是调度器（AgentDeck 里的代码，不是 agent）的事。2026-10-28 加自由模式（No template）：只开一个 Lead，它自己开子 session、派活，安全和记账仍由 AgentDeck 守；crew 和 session 命令只做成 agentdeck 命令行（不进 MCP）。分期：第一期先做 CR1 收件箱，然后 1a 自由模式（CR0、CR2 core、CR3 的 Lead 命令、CR4 的 No template、CR5 的自由模式框、CR10，命令行 CR12–CR16），再 1b 模板模式（CR2 template、CR3 的角色命令、CR4 的 Contract-first build、CR5 的任务看板、CR6、CR17–CR19）；第二期 CR7、CR8、CR11、CR20；第三期 CR9；CR21 是定位文案。进集群的 agent（2026-10-28 放宽第 6 件决定，待用户确认）：Lead 和 Worker 用 claude、codex、omp、pi，kimi 灰掉写 Needs approval for every command；自由模式的子 session 五家都行。需求见“Agent 集群”页（C0–C9），调研 DR-64、DR-65、DR-71～DR-75、DR-79。

    完成标准第一期：1a 用真 claude 当 Lead、codex 当子 session 跑通一个自由模式集群，合回 main 等你点（TC-56～TC-58）；1b 拿 AgentDeck 自己的一批任务跑一遍，你确认任务表以后不用再手动开窗口、发提示词、合分支（TC-43、TC-44）。第二期：晚上开一个集群，早上看汇报、点合并（TC-45）。

  10. M97 项

    Session

    AgentDeck 自己的 Session（存在 SQLite，窗口只引用它）：父子关系存在 Session 上，白板的窗口组只管显示；关掉窗口进程停、session 留下，Reopen 恢复名字和设置；/clear 和 compact 算同一个 Session 的新一段；换一家接着做是开一个子 session、第一条消息是交接说明，不转换对话格式。集群（CR0、CR2、CR8）建在它上面。需求见“Session”页（S0、S1），调研 DR-68～DR-70。

    完成标准Lead 开的子 session 在白板和左边栏都看得出是谁开的，关掉再 Reopen 名字和设置都回来；claude 的活能交给 codex 接着做（TC-50～TC-55）。

  11. M108 项

    Agent 接入加固

    继续跑原生 TUI，协议只当旁路（DR-66，复核 DR-01）。统一的能力报告、合格测试和 compat 记录、版本超过核对版本时自动降级、Settings › Agents 页；IS-76 单独修；codex --remote 旁路先调研（DR-67）。只深做 claude、codex，omp 等 AH1 修好后跟上，pi、kimi 走 generic 加命令行。需求见“Agent 接入”页（A0、A1）。

    完成标准pi、omp、kimi 都收到第一条消息（TC-46）；Settings › Agents 看得出每家能做什么、核对到哪个版本（TC-47）；升级到没核对过的版本自动降级（TC-48）；五家都有 compat 记录（TC-49）；agent 不能往等你的终端里打字（TC-68）。

  12. M118 项

    Skill 管理

    选 C：只读扫描五家的目录，看出重名、过时的副本和 token 占用；一处存放（AgentDeck 的库，各家目录只读当来源）；启用分全局 → 项目 → 终端三层；用各家的启动参数按项目把用户目录里的 skill 设成 Names only 或 Off；集群角色用一套预设。AgentDeck 永远不写、不删、不搬用户的 skill 目录。需求见“Skill 管理”页（K0、K1），调研 DR-80～DR-83。

    完成标准Settings › Skills 一张表看全五家的 skill（TC-74）；按项目把各家目录里的 skill 只给名字或关掉（TC-75）；集群角色各带各的 skill（TC-76）；全程不改用户的 skill 目录和配置（TC-77）。

  13. M125 项

    远程

    分三步：RM1 推送（ntfy、Bark）→ RM2 只读手机页（只听 127.0.0.1，经 tailscale serve，扫码配对，再对上 Tailscale 账号）→ RM3 手机上处理关卡、非破坏性命令和提问。第一版不支持局域网直连；手机上不放 Merge into main（待用户确认）。搜索 AgentDeck 不做，RM4 写一页说明。需求见“手机 · 远程”页（R0、R1），调研 DR-76～DR-78。

    完成标准人不在电脑前手机收到推送（TC-70）；手机上只读看收件箱、集群和终端（TC-71）；在手机上批关卡和非破坏性命令，破坏性的和合回 main 不行（TC-72）；不该进来的请求被挡住（TC-73）。

关键路径　F1 → F2 → F3 → T1 → T2 → W3 → G2 → S1 → S2 → S3 → R2。终端显示（T2）最重，越早开始越好；白板、Git、网页三条线在 M0 之后可以和它同时做。
