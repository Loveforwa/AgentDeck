每个组件做什么、怎么操作、会发生什么

这一页把 MVP 的产品需求一次说清楚：有哪些对象、每个组件由什么组成，以及点击、拖动、右键、删除时的具体表现和边界情况。开发时以这一页为准；和白板原型不一致的地方，以这一页为准。

每个组件先给一张结构图，标出各部分；再用“画面 → 操作 → 画面”的流程图说明每个操作之后界面变成什么样。虚线箭头是另一条分支。配图按原型的样式重画，并裁到和这一步有关的部分。

可交互原型：多 Agent 工作台原型（“第二版 · 白板”页）

总览与约定

MVP 要做到的事：在一块白板上同时开多个工作区，每个工作区对应一个仓库的一个分支；在工作区里开 agent 终端和网页窗口；一眼看出哪个 agent 在等你；点进去直接回复；在右侧面板提交和切换分支；终端里的本地链接直接在白板上打开。

本页用到的说法

  • 聚焦：键盘输入会进入的那个窗口。同一时间最多一个。聚焦的窗口边框变深、带阴影、在最上层。
  • 选中：用来一起移动或删除的对象，可以多个。选中只显示 1px 深色描边，不接收键盘输入。单击一个窗口会同时选中并聚焦它；框选只选中、不聚焦。
  • 散放：不在任何工作区框里的窗口。
  • 视口：白板当前显示在屏幕上的那一块区域。
  • 快捷键按 macOS 写，Windows 和 Linux 上 ⌘ 换成 Ctrl。

名词和关系

名词是什么数量关系
白板整个应用的主界面，一块可以无限平移、缩放的画布。MVP 只有一块白板。1 块
项目加入应用的一个本地 git 仓库，记录路径和几项设置（默认基础分支、worktree 存放位置等）。任意多个
工作区项目 + 一个工作目录 + 一个分支。在白板上显示为一个框。工作目录要么是新建的 worktree，要么是项目主目录本身。一个项目可以有多个工作区；主目录工作区每个项目最多一个
终端窗口运行一个命令（agent 或普通 shell）的终端。创建时就确定工作目录，之后不能更改。属于 0 或 1 个工作区
网页窗口显示一个网页或本地 HTML 文件。不绑定进程，可以在框之间自由移动。属于 0 或 1 个工作区
右侧面板显示当前工作区的源代码管理信息，跟随聚焦的窗口切换。1 个

一个分支同一时间只能在一个工作目录里检出，这是 git 的规则。所以一个分支最多对应一个工作区；想让两个 agent 并行改同一个仓库，就开两个工作区，各自一个分支。

整体布局

顶栏
左侧：白板名“我的工作台”和统计（3 个工作区 · 6 个终端）。右侧：“3 运行中”、“1 等你”（可点击，见“提醒”）、设置按钮。MVP 没有搜索。
白板
占据顶栏下方、右侧面板左边的全部区域。
右侧面板
默认宽 320px，可拖左边缘调到 280–480px，⌘B 显示或隐藏。隐藏后白板占满宽度。
左下角
当前缩放比例，例如“100%”。单击弹出：25%、50%、100%、200%、显示全部。

白板上没有工具栏。所有新建操作都通过右键菜单和快捷键完成。

白板

承载所有工作区和窗口的背景板。背景是 20px 间距的浅色点阵，缩放到 50% 以下时点阵隐藏。

操作与表现

操作表现
触控板两指滑动 / 鼠标滚轮平移白板。光标停在一个已聚焦的窗口上时，改为滚动那个窗口的内容。
按住空格拖动 / 鼠标中键拖动在任何位置平移白板。有终端聚焦时，空格会输入到终端，所以这时只能用中键或两指。
双指捏合 / ⌘ + 滚轮以光标所在点为中心缩放，范围 25%–200%。光标在窗口上也缩放白板。
单击空白处取消所有选中，取消聚焦（键盘不再输入到任何窗口），关闭打开的菜单。
在空白处按住拖动拉出选框，完全被框住的窗口和工作区框被选中。按住 ⇧ 时追加选中。
⇧ + 单击窗口或框加入或移出选中，不改变聚焦。
右键空白处菜单：新建终端 ▸（已接入的 agent 列表 + 普通终端）、新建网页窗口、新建工作区…、显示全部。新建的东西放在右键的位置，属于散放。
双击空白处弹出和右键一样的菜单。不会直接创建东西，避免误触。
从访达拖入一个文件夹是 git 仓库：在放下的位置新建这个仓库的主目录工作区；项目还没加入就自动加入。不是 git 仓库：提示“这个文件夹不是 git 仓库”，提供“初始化为 git 仓库”按钮。该项目已有主目录工作区：平移到那个框并闪一下边框。
从访达拖入 .html 文件在放下的位置打开一个网页窗口显示它。放在框里就属于那个工作区。
拖动任何东西靠近视口边缘白板自动向那个方向平移，越靠近边缘越快。
⌘1 显示全部缩放并平移，让所有框和窗口刚好放进视口，最大 100%。
⌘0缩放到 100%，以视口中心为准。

缩小后的显示

缩放低于 75% 时，终端窗口的内容区换成摘要：只显示最后 3 行输出（字号按 100% 显示，保证能读）和状态。网页窗口只显示标题和地址。标题栏和状态照常显示。单击摘要会缩放到 100%，把这个窗口移到视口中心并聚焦它。

这样做的原因是终端在被缩小后字会发糊、鼠标位置会错。缩放到 75% 及以上时显示真实终端。

空白状态

第一次打开、白板上什么都没有时，视口中间显示一句“右键新建终端，或者把一个项目文件夹拖进来”，下面两个按钮：“新建工作区”和“新建终端”。

项目

应用记住的一个本地 git 仓库。项目本身不在白板上显示，它通过工作区出现。

名称
默认是文件夹名，可改。
路径
仓库根目录。
默认基础分支
新建工作区时默认从这里分出。自动识别：远端的默认分支，其次是 main，再次是 master。
worktree 位置
默认 ~/.agentdeck/worktrees/<项目名>/，放在仓库外面，避免编辑器和文件监听把它当成仓库的一部分。
复制到新 worktree 的文件
默认 .env、.env.local。这些文件通常不在 git 里，不复制的话新目录跑不起来。
初始化命令
可选，例如 pnpm install。新建 worktree 后自动在框里开一个普通终端执行它。默认为空。

操作与表现

操作表现
添加项目三种入口：新建工作区对话框里的“添加项目…”；把文件夹拖到白板上；设置 › 项目 › 添加。都会打开选文件夹或直接用拖进来的文件夹。
选的文件夹不是 git 仓库提示“这个文件夹不是 git 仓库”，按钮“初始化为 git 仓库”（执行 git init）和“取消”。
选的是仓库里的子文件夹自动改用它所在的仓库根目录，并在提示里写明用的是哪个路径。
修改项目设置设置 › 项目 › 选中项目。改动只影响之后新建的工作区。
移除项目设置 › 项目 › 移除。白板上有它的工作区时，对话框列出这些工作区，确认后一起从白板移除（等同“仅从白板移除”）。磁盘上的任何文件都不会删除。

边界情况

  • 仓库文件夹被移动或删除：项目标记为“找不到文件夹”，提供“重新定位”和“移除”。它的工作区框显示同样的错误，框里的终端不能新建。

工作区框

白板上的一个框，代表“这个仓库的这个分支”。框里的终端都在这个目录里运行，右侧面板显示的也是这个目录的 git 状态。

新建

入口：右键空白处 › 新建工作区…，或 ⌘⇧N。在右键位置（快捷键时为视口中心）弹出一个小对话框：

项目
下拉，最近用过的在前；最后一项“添加项目…”。
目录
单选：新建 worktree（默认）/ 项目主目录。项目主目录已经在白板上时，第二项不可选，并写“已在白板上”。
分支
新建 worktree 时：单选“新分支”（默认）或“已有分支”。新分支要填分支名，可在设置里配置前缀，例如 feat/；再选“基于”哪个分支，默认是项目的默认基础分支。已有分支时从列表里选，已被其他工作区检出的分支不可选。
按钮
“创建”（↩）和“取消”（Esc）。

worktree 的目录名由分支名生成，/ 换成 -，例如 feat/oauth 对应 …/api-server/feat-oauth。

点“创建”后：框立即出现在对话框的位置，大小 720×480，标题栏显示“正在创建 worktree…”；完成后复制项目设置里的文件；设置了初始化命令就在框里开一个普通终端执行它；最后标题栏显示正常内容。

组成

标题栏
项目名（粗体）、分支名（等宽字体）。有窗口在等你时，右侧显示橙色“1 等你”；否则右侧为空，不显示改动行数之类的信息。
内容区
放这个工作区的窗口。没有窗口时中间显示“右键新建终端”。
边框
1px 浅色线；聚焦的窗口在这个框里时，框的边框变深一级。

操作与表现

操作表现
单击标题栏选中这个框，右侧面板切到这个工作区。不改变哪个窗口聚焦。
拖动标题栏移动框和里面的所有窗口。
拖动边或角改变大小。最小不能小于里面所有窗口占的范围再加 16px 边距。
双击标题栏缩放并平移白板，让这个框正好占满视口（最大 100%）。
单击分支名打开切换分支菜单，和右侧面板里的一样（规则见“源代码管理面板”）。
右键标题栏菜单：新建终端 ▸、新建网页窗口、在编辑器中打开、在访达中显示、复制路径、删除工作区…
右键框里的空白处和右键白板的菜单相同，但新建的东西放进这个框：终端的工作目录就是这个工作区的目录。
把框里的窗口拖到框的边缘框跟着变大，终端窗口不能被拖出它的框（原因见“终端窗口”）。网页窗口可以拖出去。
把框拖到和另一个框重叠允许重叠，最后选中的在上面。框不能嵌套，拖进另一个框里不会产生包含关系。
选中后按 Delete / 右键 › 删除工作区…打开删除对话框，见下。

删除工作区

对话框标题“删除工作区 api-server · feat/oauth”，正文列出将会结束的终端（“claude、zsh 会被结束”），然后是两个选项：

  • 仅从白板移除（默认）：结束框里的终端，关闭网页窗口；worktree 目录和分支都保留。以后可以在右侧面板的“仓库”区重新加回白板。可以用 ⌘Z 撤销，撤销后终端显示为“已退出”。
  • 同时删除 worktree 目录：额外删除磁盘上的 worktree 目录，分支保留。目录里有未提交的更改时，显示“有 3 个未提交的更改会丢失”，必须勾选“我知道这些更改会丢失”才能继续。不能撤销。

选第二项时多出一个复选框“同时删除分支 feat/oauth”。分支上有没合并到基础分支的提交时，旁边写“有 2 个提交没有合并到 main”。

项目主目录工作区只有“仅从白板移除”。

边界情况

  • 创建 worktree 失败（例如磁盘满、分支名不合法）：框里显示 git 的错误信息，按钮“重试”和“删除这个框”。
  • 新分支名已存在：在对话框里直接提示“分支 oauth 已存在”，并提供“改用已有分支”。
  • 有人在命令行里删掉了 worktree 目录：框显示“目录已不存在”，按钮“重新创建”和“从白板移除”。

终端窗口

运行一个命令的终端，例如 claude、codex 或你的 shell。终端本身就是标准终端，不加额外的输入框或按钮；它的价值来自和外部的连接：所在的工作区决定它的目录和右侧面板，输出里的链接和文件路径可以点，它的状态会变成提醒。

新建

  • 右键白板或框 › 新建终端 ▸ 选择一个 agent 或“普通终端”。在框里新建时目录是工作区目录；散放时目录是用户主目录 ~。
  • ⌘N：用默认 agent 新建。有窗口聚焦时放在它所在的工作区里、它的右边（放不下时框自动变大）；没有聚焦时散放在视口中心。
  • 默认大小 560×360。

组成

标题栏
状态点、命令名（等宽字体，如 claude）、标签（默认为空；可重命名，例如“主力开发”）、右侧的状态文字和时间。鼠标悬停时右上角出现“放大”和“关闭”两个按钮。
内容区
终端本体。程序自己的输入提示就是输入的地方，例如 claude 的输入框是 claude 画出来的，不是我们加的。
退出提示
程序退出后，内容区底部出现一行“进程已退出（退出码 0）”和按钮“重新启动”“关闭”。

操作与表现

操作表现
单击窗口任意位置聚焦这个终端：边框变深并带阴影，移到最上层，键盘输入进入它。点击本身也传给终端，支持鼠标的程序会收到。
聚焦时按键除了带 ⌘ 的组合，所有按键都交给终端，包括 Esc、⌃C、Tab、方向键和空格。
拖动标题栏移动窗口。在框里时不能拖出框，碰到边缘时框跟着变大。
把散放的终端拖进一个框松手后窗口回到原来的位置，并提示：“这个终端在 ~ 下运行，不能换目录。要在 api-server · feat/oauth 里新开一个 claude 吗？” 按钮“新开”和“取消”。
拖动边或右下角改变大小，最小 320×200。松手后才把新的行列数告诉程序，避免程序在拖动过程中反复重绘。
双击标题栏 / 放大按钮 / ⌘⇧↩放大到占满视口（不盖住右侧面板和顶栏）；再做一次还原到原来的位置和大小。放大状态下平移或缩放白板会先自动还原。
在内容区拖选选中文字，⌘C 复制。因为这个原因，移动窗口只能拖标题栏。
⌘V粘贴文本。多行文本作为一次粘贴发送，不会被当成多次回车。
从访达拖入文件把文件路径（带引号，多个用空格隔开）输入到终端光标处。图片也一样，交给 agent 自己读取。
滚动已聚焦且光标在窗口上：滚动终端的历史内容。未聚焦：平移白板。
悬停在链接或文件路径上出现下划线，光标变成手形。
单击本地地址（localhost、127.0.0.1）或 .html 文件路径在白板上打开网页窗口，放在这个终端右边、同一个框里（框会变大）。同一个工作区里已经有显示同一个端口的网页窗口时，在那个窗口里打开，并闪一下它的边框。⌘ + 单击总是新开一个。
单击其他网址用系统默认浏览器打开。
单击文件路径（如 src/auth/oauth.ts:44）在设置里选的编辑器中打开，并跳到那一行。相对路径按终端的工作目录解析；文件不存在时不显示为可点击。
右键标题栏菜单：重命名、复制工作目录、清屏、重新启动、在其他工作区新开同款 ▸、关闭。
右键内容区菜单：复制、粘贴、全选、清屏。程序开启了鼠标模式时，右键交给程序。
关闭（悬停出现的 ×、⌘W、选中后 Delete）程序还在运行：确认“结束 claude？正在进行的任务会中断。”按钮“结束并关闭”和“取消”。程序已退出：直接关闭，可以 ⌘Z 恢复。
重新启动用同一个命令、同一个目录重新运行，内容区清空。agent 支持接着上次对话时（例如 claude 的 --continue），按钮旁边的下拉里多一项“接着上次的对话”。

为什么终端不能换框

程序启动后，它的工作目录就固定了，外部改不了。如果允许把运行中的终端拖进别的框，界面会显示它属于新框，实际上它还在旧目录里改文件，右侧面板显示的 git 状态就和它真正改的东西对不上。所以终端在哪个框里创建，就一直属于那个框。

边界情况

  • 命令找不到：内容区显示“找不到命令 claude”，下面是“打开设置修改命令”和“改用普通终端”。
  • 程序以非 0 退出码退出：状态为“出错”，退出提示写出退出码。
  • 终端服务本身崩溃：所有终端显示“终端服务意外退出”，顶栏出现“全部重新启动”。

终端状态和时间

每个终端都有一个状态，显示在标题栏的点和文字上，并汇总到工作区框、顶栏和系统通知。

状态标记什么时候进入标题栏右侧文字
启动中浅色空心点刚创建，程序还没有任何输出启动中
运行中实心黑点收到“开始处理”的通知，或有新输出运行 4 分（这一轮已经运行多久）
等你橙点；窗口未聚焦时边框也变橙收到“需要批准”或“等待输入”的通知等你批准 · 3 分 / 等你回复 · 3 分
空闲空心点一轮结束；没有通知能力的程序 3 秒内没有新输出空闲 · 12 分
已退出灰色短横进程以 0 退出已退出
出错灰色短横，文字为强调色进程以非 0 退出，或启动失败出错 · 退出码 1

时间怎么写

  • 不到 1 分钟写“刚刚”；不到 1 小时写“n 分”；不到 1 天写“n 小时”；更早写日期，例如“10月21日”。
  • 每 30 秒更新一次。
  • 悬停在状态文字上，显示准确时间，例如“开始于 14:32”。

状态从哪里来

程序来源能识别的状态
claude（Claude Code）它自带的钩子：提交提示词、发出通知、一轮结束时回调 AgentDeck运行中、等你、空闲，全部准确
codex它的 notify 配置在一轮结束时回调；需要批准的提示从输出里识别运行中、空闲准确；等你批准尽量识别
其他 agent、普通终端只看输出运行中、空闲；不会进入“等你”

钩子写在工作区里不会被提交的本地配置文件中，只对从 AgentDeck 启动的会话生效。每个 agent 具体写哪个文件、用哪些事件，以它当前版本的文档为准，由 agent 接入模块负责。

网页窗口

在白板上显示 dev server 页面或本地 HTML 文件，和产生它的终端放在一起。

新建

  • 单击终端输出里的本地地址或 .html 路径（见“终端窗口”）。
  • 右键白板或框 › 新建网页窗口。打开一个起始页，列出这个工作区的终端里出现过的本地地址（例如 localhost:3000 · 来自 zsh），单击即打开。散放时列出所有终端出现过的地址。
  • 从访达拖入 .html 文件；⌘T 新建，规则同 ⌘N。
  • 默认大小 640×420。

组成

工具栏
后退、前进、刷新、地址栏、来源（灰字，例如“来自 zsh · pnpm dev”）、在系统浏览器打开、放大、关闭。
内容区
网页本身。

操作与表现

操作表现
单击未聚焦的网页窗口只聚焦，这一下不传给网页，避免误点页面里的按钮。聚焦后正常操作页面。
拖动工具栏的空白处移动。可以拖进、拖出任何框：松手时窗口中心落在哪个框里，就属于哪个框；拖动中经过的框会高亮。
单击地址栏 / ⌘L编辑地址，↩ 打开，Esc 取消。只接受 http、https 和本地文件。
后退、前进、刷新和普通浏览器一样，快捷键 ⌘[ ⌘] ⌘R。
滚动聚焦时滚动网页，未聚焦时平移白板。
拖动边或右下角改变大小，最小 320×240。
放大和终端相同。
在系统浏览器打开用默认浏览器打开当前地址。
关闭（×、⌘W、选中后 Delete）直接关闭，不确认。⌘Z 可以恢复到关闭前的地址。

边界情况

  • 地址没有响应（服务没启动或已停止）：内容区显示“localhost:3000 没有响应。dev server 可能还没启动，或者已经停止。”按钮“重试”。
  • 页面拒绝被嵌入显示：内容区显示“这个页面不允许在白板里显示”，按钮“在系统浏览器打开”。
  • 本地 HTML 文件被删除：显示“找不到文件”和文件路径。
  • 需要登录的页面在白板里可能保持不了登录状态。MVP 里遇到时用“在系统浏览器打开”，独立窗口模式放在 v0.2。

源代码管理面板

右侧面板，显示当前工作区的 git 状态，操作方式参照 VS Code 的源代码管理。

显示哪个工作区

  • 跟随聚焦的窗口所在的工作区。单击框的标题栏也会切换。
  • 聚焦散放的窗口时显示：“这个窗口不属于任何工作区。”
  • 面板顶部显示项目名和工作目录路径，单击路径复制。

组成与操作

区域内容与操作
分支按钮显示当前分支，旁边写“比 main 多 3 个提交”。单击打开下拉：顶部搜索框；本地分支列表，当前分支打 ✓；被其他工作区检出的分支灰显，写“在 fix/rate-limit 框里”，单击它会跳到那个框；最后一项“新建分支…”，从当前提交新建并切换过去。
提交框多行输入框写提交信息，⌘↩ 提交。按钮文字：有暂存的文件时“提交 2 个文件”；没有暂存时“提交全部 5 个更改”，第一次使用会确认一次。提交信息为空时按钮不可用。
暂存的更改 / 更改两组，各自按文件夹折叠成树。每行：文件名、所在文件夹（灰字）、状态字母（M 修改、A 新增、D 删除、R 重命名、U 未跟踪、! 冲突）。组标题上的 + / − 全部暂存或全部取消暂存。
悬停在文件行上出现“暂存”（+）或“取消暂存”（−）和“放弃更改”（↶）。
单击文件面板内显示这个文件的差异（只读），顶部有“返回”和“在编辑器中打开”。
双击文件在编辑器中打开这个文件。
放弃更改确认“放弃 oauth.ts 的更改？这不能撤销。”未跟踪的文件改为“把 notes.md 移到废纸篓？”，移到废纸篓而不是直接删除。
仓库列出当前项目的所有工作目录（主目录和各个 worktree）：分支名、相对路径、↑ 提交数。在白板上的：单击平移到那个框，并聚焦它上次聚焦的窗口。不在白板上的（例如在命令行里建的）灰显，单击“添加到白板”。
提交记录当前分支最近 20 个提交：短哈希、信息、相对时间。从基础分支分出的位置画一条分隔线，下面写“以下是 main 上的提交”。单击一行复制哈希。

切换分支前的检查

  • 有未提交的更改：对话框“有 3 个未提交的更改”，按钮“带着更改切换”（git 允许时才出现）、“先存起来再切换”（存成 stash，切回这个分支时提示恢复）、“取消”。
  • 有 agent 正在这个目录里运行：另外写一句“claude 正在这个目录里运行，切换分支会改变它看到的文件。”
  • git 拒绝切换（例如有冲突）：显示 git 的原始错误信息。

什么时候刷新

  • 工作目录里的文件变化后 300ms 内刷新。
  • 提交、暂存、切换分支后立即刷新。
  • 面板右上角有手动刷新按钮。

边界情况

  • 提交失败（例如 pre-commit 钩子不通过）：提交框下方显示命令输出，可以展开查看全部。
  • 仓库处于合并或变基中：分支按钮旁显示“合并中”，冲突文件单独成组排在最上面，提交按钮文字变成“完成合并”。

Agent 与设置

设置从顶栏右侧的设置按钮打开，是一个独立的窗口，不在白板上。

分组内容
Agent自动检测已安装的 agent（claude、codex、gemini、aider、opencode 等）：名称、命令路径、版本、状态来源（钩子或输出）。没找到的显示“未找到”和安装说明链接。可以手动改命令路径。可以添加自定义命令：名称、命令、参数、环境变量，添加后出现在“新建终端”菜单里。选择默认 agent，⌘N 用它。
项目项目列表和每个项目的设置（见“项目”）。
通用打开文件用的编辑器（VS Code、Cursor、Zed 或系统默认）；新分支名前缀；应用在后台时发系统通知（默认开）；退出时有运行中的终端要确认（默认开）。

MVP 只为 claude 和 codex 接钩子，其他 agent 和自定义命令都按“只看输出”识别状态。

提醒

保证你不用盯着每个窗口，也知道哪个 agent 停下来等你。

  • 窗口：状态点变橙；窗口未聚焦时边框也变橙。
  • 工作区框：标题栏右侧显示“1 等你”。
  • 顶栏：“1 等你”按钮。单击依次跳到每个在等你的窗口：平移白板把它放到视口中间并聚焦。⌘J 效果相同。
  • 应用在后台：发系统通知，例如“api-server · feat/oauth 里的 claude 在等你批准”。单击通知，应用回到前台并跳到那个窗口。程序坞图标的角标显示在等你的数量。
  • 聚焦一个在等你的窗口后，它的橙色边框消失，状态点仍是橙色，直到 agent 继续运行。

删除与撤销

对象怎么删要不要确认结果能否 ⌘Z
网页窗口×、⌘W、选中后 Delete不确认关闭能
终端（已退出）同上不确认关闭能，恢复为已退出状态
终端（运行中）同上确认结束进程并关闭不能
工作区框选中后 Delete、右键 › 删除工作区…对话框见“工作区框 › 删除工作区”只有“仅从白板移除”能
多选Delete里面有运行中的终端或工作区时，确认一次，列出会被结束的终端和会被移除的工作区工作区一律按“仅从白板移除”处理能，但已结束的进程恢复为已退出
项目设置 › 项目 › 移除确认只从应用里移除，磁盘不动不能

⌘Z 能撤销的是白板上的操作：移动、改大小、放大还原、新建和关闭窗口、仅从白板移除的工作区。结束进程、git 操作和删除磁盘上的目录都不能撤销。焦点在网页或输入框里时，⌘Z 交给它们自己。

保存与重启

  • 自动保存：白板的平移缩放位置、所有框和窗口的位置大小、窗口类型、命令和标签、网页地址、右侧面板的宽度和开关。改动后半秒内写入，没有保存按钮。
  • 退出：有运行中的终端时确认“有 3 个终端在运行，退出会结束它们。”按钮“退出”和“取消”。
  • 重新打开：布局完全恢复；网页窗口重新加载；终端显示“上次的会话已结束”和“重新启动”按钮（同一个命令、同一个目录），内容区为空。有两个以上这样的终端时，顶栏出现“全部重新启动”。
  • 终端的历史输出在重启后恢复，以及关掉应用后 agent 继续在后台运行，都不在 MVP 里。

验收场景

MVP 完成时，下面每一条都要能从头走到尾。

  1. 第一次打开应用，把 api-server 文件夹拖到白板上，得到它的主目录工作区。
  2. 右键 › 新建工作区，基于 main 新建分支 feat/oauth；框出现，worktree 建好，.env 已复制，pnpm install 在框里的终端中自动运行。
  3. 同一个仓库再建 fix/rate-limit 工作区；两个框里各开一个 claude，同时改代码，互不影响。
  4. 其中一个 claude 请求批准命令：2 秒内它的窗口变橙，框显示“1 等你”，顶栏显示“1 等你”；应用在后台时收到系统通知。
  5. 按 ⌘J 跳到那个窗口，直接按 y 批准，状态回到运行中。
  6. 在框里开普通终端运行 pnpm dev，单击输出里的 localhost:3000，网页窗口出现在它右边、同一个框里。
  7. 聚焦 claude，右侧面板显示 feat/oauth 的更改；暂存两个文件，写提交信息，⌘↩ 提交，提交记录里出现这一条。
  8. 在面板里尝试切换到 fix/rate-limit：它显示“在 fix/rate-limit 框里”，单击后白板跳到那个框。
  9. 缩小到 50%：所有终端显示最后 3 行和状态；单击其中一个，回到 100% 并聚焦它。
  10. 退出应用再打开：所有框和窗口的位置不变，终端显示“上次的会话已结束”，单击“重新启动”可以继续使用。
  11. 删除 fix/rate-limit 工作区并勾选删除目录：有未提交更改时必须先勾选确认；完成后磁盘上的目录消失，分支还在。
