DR-01

agent 的对话是在白板上的真终端里，不是我们自己画的界面

已解决
原来以为

在 AgentDeck 自己的面板里渲染每个 agent 的对话，统一样式。

实际情况

每家 agent（claude、codex、gemini）都有自己的 TUI，功能和快捷键一直在变；自己重画等于给每家重做一遍界面，永远追不上。

决策

白板上直接放真实的终端，agent 在里面原样运行；AgentDeck 只管窗口、工作区、状态和 Git。

好处

不用适配每家界面，agent 升级我们不用跟；用户在里面的操作和平时一模一样。

代价

没法统一对话的样式；“谁在等你”这类信息只能从外面推断（见 DR-07、DR-12）。2026-10-27 复核过 ACP、codex app-server、Claude Agent SDK，结论不变（DR-66）：claude 走 SDK 要改用 API key，ACP 上 claude、codex 都靠第三方适配器、session/fork 还是 Draft。

DR-02

不要左侧栏，也不要每个框上的 +/− 改动数

已解决
原来以为

左侧栏放会话列表；每个工作区框右上角显示增删行数。

实际情况

白板本身就能看全局，左侧栏重复且占地方；改动数在框上没有可操作的东西，只是噪音。

决策

去掉左侧栏，操作都走右键和触控板；改动只在右侧源代码管理面板里看。

好处

白板面积大，界面更安静，更接近“工具”而不是“AI 产品”。

代价

新用户不知道右键能做什么，需要空白状态里给提示按钮。

出处：原型评论 fb33f60b · 旧编号 A2

DR-03

界面全英文，文档用中文

已解决
原来以为

界面文案用中文。

实际情况

产品以后面向的用户和生态都是英文的，界面文字和 agent 输出也是英文。

DR-64

复杂任务的多 agent 协作：让一个 agent 当总指挥，还是 AgentDeck 按模板调度

进行中
原来以为

（N1 之后的设想）agent 用 open_terminals 自己开子 agent、自己分工，AgentDeck 只负责把窗口摆出来；“claude 做完交给 codex 审”这种两步流程已经能手动做到。

实际情况

2026-10-27 推演 AgentDeck 自己的开发流程（先定 contracts、再分线并行、换家审、按依赖合并）：让一个 agent 当总指挥时，上下文满了或压缩后会忘任务表，断了接不上；它说“做完了、检查过了”没人核对；改了别的线的目录、动了 contracts 没人拦；只能用它自己那家的额度，额度一完整个集群停；你还是得守着它。这些都不需要模型的判断，是确定的规则。真正需要模型的是拆任务、写代码、审代码、解冲突。2026-10-27 竞品对照（DR-79）：TermCanvas 的 Hydra、AgentGrid、Nodeterm 都是 Lead agent 自己管流程；Claude 的 agent teams、Projects 只用一家。还没看到确定的调度器加关卡的做法。

决策

2026-10-27 用户定：模板定结构（角色、阶段、关卡、上限），agent 填内容（任务表、代码、审查意见）。调度器是 AgentDeck 里的一段代码，不是 agent：它保存任务表（只存在 AgentDeck 里，不往仓库写，agent 用 crew 工具读写）、按依赖派活、给每个任务开 worktree（crew/<name>/<任务>）和终端、自己跑检查命令、比对任务的 owns 目录（越界打回）、锁住 contracts（要改走关卡）、换一家审（最多两轮）、merge --no-ff 进集群分支（冲突才开 Integrator）、额度用完换家或等恢复、重启后对账接上。界面上叫 Crew；默认分工总设计 claude、实现 codex（用完换 claude）、审查 claude、验收 codex；同时最多 3 个 agent；收件箱（CR1）先单独做；第一期只给 claude、codex、omp（DR-65）。分三期：CR0–CR6 只有 Contract-first build 一个模板，CR7–CR8 加 Integrator、QA、汇报、换家、整夜跑，CR9 开放模板文件和其余四种模板。2026-10-28 主 agent 补：crew 工具做成 agentdeck 命令行（agentdeck crew …），不进 AgentDeck MCP，说明只给 Lead（DR-72，CR3、CR12–CR17）。模板之外加自由模式（No template）：只开一个 Lead，流程交给它，安全和记账仍由 AgentDeck 守；第一期先做 CR1 收件箱，再做 1a 自由模式、1b 模板模式，互转放第二期（DR-71，CR10、CR11）。一个任务对应一串 session（实现者、每轮审查者、交接后的接班者），CrewTask 存 SessionId、不存 TerminalId；换一家接着做用 SE6 的交接（DR-68、DR-69）。Lead 不记进度但负责跟你聊进度：进度以任务表和 Decisions 为准，Lead 说之前先读 AgentDeck 生成的进度摘要，压缩、重开、换一家后从摘要接上；收件箱管要你拍板的事，Lead 能建议、不能代按，第二期按授权只答 worker 的问题（DR-73、DR-75，CR18–CR20）。进集群的名单见 DR-65。2026-10-28 补（第二轮）：研究和竞赛（第 10 点）同样是“调度器加记账”的思路：分数由 AgentDeck 在提交上跑锁住的打分命令算、长训练由 Jobs 看着、Kaggle 提交只走 Submit 关卡；研究模板放到 CR9 之后（DR-85）。集群结束时，研究集群先给登记过的产物存快照，再清 worktree（DR-91）。

好处

进度和规矩不靠模型记，断了能续、能核对；能跨家用额度；你只在关卡（确认任务表、改接口、卡住、合回 main）上出现；第一个模板就是我们自己在用的流程，能拿 AgentDeck 自己的任务验证。

代价

调度器、crew 工具、集群框都是新东西，第一期就有 7 个任务；模板的形状是我们定的，第三期才开放给用户改；agent 不守 crew 工具的约定（比如不跑 agentdeck crew done）时要靠超时和检查兜底。

AgentDeck 里的 session 是什么：窗口、tmux 会话、agent 会话记录之外要不要有自己的 Session
