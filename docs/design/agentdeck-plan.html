AgentDeck · 实施方案 · 2026-10

从白板原型到能用的第一版

这份方案回答六件事：用什么技术、最小能用的版本做哪些、界面怎么不显得像 AI 做的、功能怎么拆、怎么让多个 agent 并行开发它，以及怎么保证以后改一个模块不牵动全身。

技术栈
Electron + TypeScript + React，白板用 React Flow。终端进程由 tmux 托管，界面用 xterm.js 显示；Git 直接调用系统的 git 命令，不监听文件。
MVP
白板上开工作区框，框里跑 agent 终端，看得到谁在等你，点进去直接回复，右侧面板提交代码，终端里的 localhost 链接在白板上打开。
不牵一发
模块之间只通过 contracts 包里的接口通信；窗口类型和 agent 都用注册表接入；依赖方向由 CI 检查。
并行开发
先由一个 agent 搭好骨架和接口，之后拆成 5 条线，每条线一个 worktree、只改自己的目录。

技术选型

决定选型的是两件最难的事：在可以缩放的白板里放真实的终端和真实的网页。终端这边，进程交给 tmux 管，我们只负责显示和同步信息；网页这边，Electron 有成熟的现成方案，所以第一版用它。

层选择为什么没选的方案
桌面外壳Electron + electron-vitexterm.js 是 VS Code 在用的终端组件，最成熟。主进程能改写 localhost 的响应头，网页窗口才能嵌进白板。MVP 只支持 macOS 和 Linux，Windows 需要 WSL（tmux 没有原生 Windows 版）。Tauri 2：体积小，但子 webview 是原生图层，不能跟着白板一起平移缩放。等产品稳定后再评估。
语言与仓库TypeScript，pnpm workspaces 单仓多包前后端一种语言；每个模块一个包，边界清楚，agent 好分工。
界面React 18 + Zustand（按领域分 store）React Flow 和 xterm 封装都是 React 生态；Zustand 按 terminals、workspaces、git 各自一块，互不影响。Redux：样板代码多，对这个规模没必要。
白板React Flow（@xyflow/react，MIT）节点就是普通 React 组件；自带平移缩放、拖角缩放（NodeResizer）、分组节点（可直接当工作区框）和小地图。tldraw：画图能力更强，但用在正式产品里需要购买授权，而且我们不需要画笔类功能。
终端进程tmux，AgentDeck 自己的独立实例（tmux -L agentdeck）和配置，关掉快捷键前缀agent 进程归 tmux 管：关掉应用也继续跑，重开直接接上，历史输出由 tmux 保存；你也能在自己的终端里 tmux attach 接上同一个会话。需要的信息 tmux 都能给：当前目录和命令（display-message）、最后几行（capture-pane，给缩小后的摘要用）、输出抄送（pipe-pane，用来找 localhost 链接）、有没有新输出（monitor-activity / monitor-silence）。不影响你自己的 tmux。node-pty 直接起进程：应用一退出进程就没了；看不见的终端也得一直接收输出；重启后恢复历史要自己做。
终端显示@xterm/xterm（fit、webgl 插件）+ node-pty，只用来接上 tmux 会话只为视口里的终端开一个 tmux attach 显示，移出视口就断开，不占资源。连接放在 Electron 的 utilityProcess 里，出问题不会拖垮界面。
Git系统 git 命令（可用 simple-git 包一层）worktree、暂存、提交图这些功能都完整，行为和你在命令行里看到的一致。isomorphic-git：不支持 worktree。
git 刷新时机不监听文件，按事件刷新只在三种时候刷新：切换聚焦的窗口或工作区；agent 一轮结束（钩子通知）；你自己提交、暂存、切换分支之后。另有手动刷新按钮。少一个模块，多个 worktree 时也没有额外开销。@parcel/watcher 监听文件：每个 worktree 都要监听，大仓库下开销大；agent 场景下没必要实时刷新。
本地数据SQLite（better-sqlite3）存白板布局、会话信息（窗口对应哪个 tmux 会话）、skills 库索引。终端历史由 tmux 保存，不另存。
网页窗口iframe + 主进程去掉 localhost 的 X-Frame-Options / frame-ancestors；本地 HTML 走自定义协议能像普通 DOM 一样跟着白板缩放。Electron <webview>：隔离更好，作为登录类页面的退路（见风险 3）。
agent 状态优先用 agent 自带的通知钩子，退路是 tmux 报告的输出活动Claude Code 和新版 Codex 都有 hooks（UserPromptSubmit、PermissionRequest、Stop 等事件），启动时临时注入，不改用户自己的配置；旧版 Codex 退回 notify；钩子回调到应用的本地端口，比猜输出准。没有钩子的程序，用 tmux 的 monitor-activity / monitor-silence 判断运行中和空闲，不需要打开终端界面。只靠正则匹配输出：各家 TUI 一改版就失效。
测试Vitest（单元）+ Playwright 的 Electron 模式（端到端）每个包能单独测，agent 改完自己能验证。
模块边界dependency-cruiser，放进 CI谁能依赖谁写成规则，越界的提交直接不通过。只靠约定：并行开发时一定会被打破。

动手前先验证四个风险

每个用半天做一个最小试验，结论会影响后面的设计。

风险 1终端在缩放的白板里会发糊、选区错位

xterm 用 canvas 画字，外层被 CSS 缩放后字会模糊，鼠标坐标也会对不上。所以想放下更多窗口时，靠拖边框把窗口改小，字号不变；终端被拉到小于 320×200 时换成摘要卡，只显示最后几行和状态。白板整体缩放只留 ⌘ + 滚轮作为备用，低于 75% 时同样换成摘要卡。真正的 xterm 只在 1:1 尺寸下渲染。摘要卡的内容用 tmux 的 capture-pane 读，不需要打开终端界面。原型第 3 屏就是这个状态。

风险 2正在运行的 agent 换不了工作目录

进程启动后，它的当前目录就改不了。所以第一版规定：终端在创建时就绑定它所在的框；把运行中的终端拖进别的框，只是挪位置，同时提示“在这个框里新开一个同款 agent”。不要做成看起来已经切换了目录、其实没切的样子。

风险 3嵌进来的本地页面可能登录不了

页面在 iframe 里时，它的 cookie 算第三方 cookie，SameSite=Lax 的登录态会丢。普通页面用 iframe；遇到需要登录的页面，提供“切换为独立窗口模式”，改用 <webview>，它有自己独立的会话。

风险 4经过 tmux 一层后，终端手感变差

按键、滚动、鼠标、颜色都要经过 tmux 转一层，配置不对就会出现快捷键被吃掉、滚动变成翻 tmux 历史、颜色变淡这类问题。要先用 claude 和 codex 实测：关掉前缀键、打开鼠标支持、真彩色、bracketed paste、扩展按键都能正常工作；同时测在白板上平移时，终端反复接上、断开的速度够不够快。

整体结构

界面进程只负责显示和交互，所有碰系统的事（tmux、git、网络头）都在主进程或独立进程里，通过一层类型化的 IPC 调用。agent 进程本身跑在 tmux 里，不在 AgentDeck 的任何进程里。

  H --> M

怎么做到改一个模块不牵动全身

核心是三条：只通过接口通信、用注册表接入、边界交给机器检查。剩下几条是让这三条真正落地的办法。

  1. 只通过 contracts 通信。每个服务在 contracts 里有一份接口和事件定义，界面和服务都只认它。比如把 git-service 从命令行实现换成别的实现，界面一行不用动。
  2. 注册表代替 if/else。窗口类型（终端、浏览器，以后的 diff 查看器、笔记）和 agent（claude、codex、gemini、自定义命令）都通过注册表接入。加一种窗口或一个 agent，就是加一个文件夹，再加一行注册。
  3. 数据单向流动。服务发出事件，对应的 store 更新，组件只读 store。组件之间不互相调用，白板也不知道终端内部怎么实现。
  4. 依赖方向写成规则。ui/* 只能依赖 contracts 和 design-tokens；服务不能依赖 ui；各个 widget 之间、各个 adapter 之间不能互相引用。dependency-cruiser 在 CI 里检查。
  5. 每个模块自带假实现。有了假 tmux 和假 GitService，做界面的人不用等服务写完，做服务的人也不用开界面就能测。
  6. 样子只在 tokens 里改。组件里禁止写颜色值（lint 规则拦住十六进制颜色），以后换风格只改 design-tokens。
  7. 每个包一份 AGENTS.md。写清楚职责、对外接口、不许碰的目录、怎么跑测试。这是写给并行开发的 agent 读的，也是以后你自己回来改代码时的入口。

三个核心接口的样子：

// packages/contracts/src/terminal.ts
export interface TerminalHost {
  // 会话：在 AgentDeck 自己的 tmux 实例里创建，应用退出后继续存在
  create(req: { cmd: string; args: string[]; cwd: string; env?: Record<string, string> }): Promise<{ id: string }>;
  kill(id: string): Promise<void>;
  list(): Promise<{ id: string; cwd: string; command: string; alive: boolean }[]>;   // 重开应用时用来接上
  // 显示：只为视口里的终端接上，移出视口就断开
  attach(id: string, cols: number, rows: number): Promise<{ viewId: string }>;
  detach(viewId: string): void;
  write(viewId: string, data: string): void;
  resize(viewId: string, cols: number, rows: number): void;
  // 不用接上也能拿到的信息
  lastLines(id: string, n: number): Promise<string[]>;                          // 缩小后的摘要
  attachCommand(id: string): string;                                            // 在系统终端里接上用
}
export type TerminalEvent =
  | { type: 'data'; viewId: string; data: string }       // 只有接上的终端才有
  | { type: 'activity'; id: string }                     // 有新输出
  | { type: 'silence'; id: string }                      // 一段时间没有输出
  | { type: 'link'; id: string; url: string }            // 输出里出现了 localhost 地址
  | { type: 'exit'; id: string; code: number };

// packages/contracts/src/agent.ts
export interface AgentAdapter {
  id: string;                                   // 'claude' | 'codex' | 'gemini' | 'custom'
  label: string;
  detect(): Promise<{ installed: boolean; version?: string }>;
  launch(ws: Workspace): { cmd: string; args: string[]; env?: Record<string, string> };
  statusSource: 'hooks' | 'idle';               // 状态从钩子来，还是靠输出空闲判断
  installHooks?(ws: Workspace, callbackUrl: string): Promise<void>;
  writeProfile?(ws: Workspace, profile: Profile): Promise<void>;   // v0.2：skills / MCP
}

自动存档的做法：用一个临时 index（设置 GIT_INDEX_FILE）执行 git add -A、write-tree、commit-tree，再用 update-ref 写到 refs/agentdeck/checkpoints/…。这样连未跟踪的文件也能存下来，又不碰你真正的暂存区和分支历史。

MVP 怎么做

判断标准只有一个：你能不能用它过完一整天真实的开发。为此需要的最小闭环是：在白板上开三个工作区，各跑一个 agent；一眼看出谁在等你；点进去直接回复；在右侧提交；点 dev server 的链接，在白板上看效果。

M0

骨架（一个 agent 串行完成）

单仓多包、contracts 第一版（含 TerminalHost）、design-tokens、window-shell 空壳、窗口和 agent 的注册表、CI（类型检查、lint、依赖边界、单元测试）、假 tmux 和临时仓库夹具。同时做完风险 4 的 tmux 配置试验，定下 AgentDeck 自带的 tmux 配置。

完成标准：pnpm dev 打开一块空白板，用假 tmux 在上面显示一个正在回放输出的终端窗口。

M1

白板和终端

右键新建终端，进程在 AgentDeck 的 tmux 实例里运行；拖动、缩放、放大；只为视口里的终端接上显示，拉小后显示摘要卡；退出再打开时布局恢复、终端自动接上；右键 › 在系统终端里打开。

完成标准：同时开 6 个真实的 claude / codex 终端，打字没有可感知的延迟；退出应用再打开，终端还在跑，历史输出都在；在系统终端里接上同一个会话，两边输入同步。

M2

工作区和 Git

右键画框，选仓库，自动建 worktree 和分支；框里新开的终端目录正确；右侧面板跟随聚焦的窗口，只在切换聚焦、agent 一轮结束、自己操作 git 之后刷新；暂存、提交、切换分支。

完成标准：同一个仓库开两个框，两个 agent 同时改代码互不影响；在面板里提交后，git log 里看得到。

M3

状态和网页窗口

“等你处理”状态（先接 Claude Code 的钩子，其他 agent 用 tmux 的输出活动判断）；agent 一轮结束时通知右侧面板刷新；终端里的 localhost 链接点开就是白板上的网页窗口。

完成标准：某个 agent 停下来问你问题，2 秒内它的窗口亮起橙点；点 dev server 链接，页面在同一个框里打开。

M2 做完以后，就可以用 AgentDeck 自己来开发后面的版本。

多 agent 并行开发

M0 必须一个 agent 串行做完，因为所有人的接口都在这一步定下来。之后拆成 5 条线，每条线一个 worktree、一个分支，只改自己负责的目录。

线负责的目录交付依赖
1 终端tmux-host、ui/widgets/terminal、port-watchtmux 会话管理、只为视口里的终端接上显示、摘要卡内容、链接识别、在系统终端里打开、重开应用后自动接上window-shell（M0 已有）
2 白板ui/canvas、ui/window-shell右键菜单、框、拖动缩放、布局保存只用假窗口，不依赖别的线
3 Gitgit-service、workspace-service、ui/panels/scmworktree 生命周期、源代码管理面板、按事件刷新（不监听文件）用临时仓库测试，不依赖界面；“一轮结束”事件来自第 4 条线，先用假事件
4 Agentagent-adaptersclaude、codex、自定义命令；Claude Code 钩子回调；发出“一轮结束”事件用假 tmux 测试
5 网页ui/widgets/browser、主进程里的响应头改写和自定义协议网页窗口、后退刷新、独立窗口模式window-shell

规则

  • 只改自己的目录。需要改 contracts 时先停下来，单独提一个只改 contracts 的小提交，合进 main 后其他线再 rebase。
  • 每条线都有假实现可用，不等别人写完。
  • 每完成一个里程碑集成一次，按 contracts → 服务 → 界面的顺序合并。
  • 提交前跑 pnpm check（类型检查、lint、依赖边界、本包测试）。
  • 另开一个只读的 agent 做审查，只提意见不改代码。

界面怎么做到不像 AI 做的

“AI 味”主要来自几种被用滥的做法：紫蓝渐变、发光和毛玻璃、每个东西都配彩色头像、✨ 和 emoji、到处都是圆角卡片和阴影、“Smart”“AI is doing it for you”这类文案。反过来，参照专业工具的克制：VS Code 的源代码管理、Figma 的画布、终端本身。

要做的

  • 暖灰加墨黑，只留一个强调色给“需要你处理”
  • agent 名字用等宽字写命令名：claude、codex
  • 一种界面字体加一种等宽字体，字号只用 11 / 12 / 13 / 15
  • 用 1px 线分隔；只有浮起来的东西（菜单、聚焦窗口、拖动中）才有阴影
  • 圆角固定三档：按钮 6、窗口 8、框和面板 12
  • 一套线性图标（如 Lucide，1.5 线宽）
  • 界面文案全部用英文，状态写成事实：“Needs approval”“Running · 12m”
  • 动效 120–160ms、减速曲线，跟随系统的减少动效设置

不做的

  • 渐变、发光、毛玻璃背景
  • 给每个 agent 配彩色头像或 logo
  • emoji、✨、闪光图标
  • 每块内容都套圆角卡片加阴影
  • 用颜色区分所有状态（运行中用黑点、空闲用空心点就够了）
  • “Smart …”“AI is working on it for you…”“✓ Perfect!”这类文案
  • 空状态放插画
  • 弹跳、缩放进场的动画

落地办法：先写 design-tokens，再写组件；lint 禁止组件里出现颜色值；每个里程碑截一张全屏图，对照上面两列检查一遍。
