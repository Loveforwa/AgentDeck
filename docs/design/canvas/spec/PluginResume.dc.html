PL4 · Auto-resume：被额度打断的任务，恢复后自己接着做

草案，待定 接 PL3 · 任务 PL4–PL9 · IS-113～IS-115 · DR-84 · 依赖 N10、CR1、CR8

额度是按账号算的：一个账号用完，同一家的几个终端会一起停在半路，里面的后台子 agent 也跟着断。Prompt queue（PL3）只管“排好的下一件事”，队列是空的就什么都不发。Auto-resume 补上另一半：恢复后先让每个被打断的终端把手上的事做完、把断掉的子 agent 接回来，再按 PL3 发排着的提示词。同一账号的终端一起看、一起续、一起取消。agent 自己会续的（claude 2.1.234 起），AgentDeck 不重复发，只盯着它续没续上。

按账号归一组：账号 = agent + 它的配置目录（CLAUDE_CONFIG_DIR / CODEX_HOME，没设就是 ~/.claude、~/.codex）。一个终端撞上，同一账号的终端都标成“受限”，包括当时空闲、自己没撞的那个（它排着的提示词也等这次恢复）。 收件箱（CR1，按集群分组的样子见 C4）：一个账号一条 “Usage limit”，列出被打断的终端和几点续。会自己续的不算进 “Needs you” 的数字，放在 PAUSED 一组；读不到恢复时间、连撞两次、睡过头了，才进 WAITING FOR YOU 算数。 Don’t resume：这一组都不续（排着的提示词也不发，PL3 队列变成 paused）。取消某一个：去掉那一行的勾。Resume now：恢复时间读不到、或你买了额度时用；恢复时间还没到时灰掉。 终端书签：被打断的终端底边挂 “Paused · resumes 9:01pm”（黄点，和 PL3 等恢复的书签一样），开着 Prompt queue 时合成一个书签。 顶栏按钮在只有 PAUSED 时写 “Needs you · 0 · 2 paused”，灰色。

3 · 怎么认出“干到一半被打断”
情况怎么认恢复后做什么 这一轮是被额度结束的claude：StopFailure 钩子 error: "rate_limit"，或会话记录最后一条是 error: "rate_limit" 的那一行（之后没有成功的回答）。codex：最后一个 task_complete 带 codex_error_info: "usage_limit_exceeded"。发续跑提示（第 4 节）；claude 自己会续时不发，只看它续没续上 同一账号，当时空闲这个终端上一轮正常结束（Stop / 没有 error 的 task_complete），是因为别的终端撞了才标成受限。不续跑；排着的提示词照 PL3 发 撞完以后你接手了之后在这个终端打过字、发过消息、按过 Esc（状态机的 noteInput，或新的 UserPromptSubmit）。不管它，书签写 “you took over” 后收起 只有后台子 agent 撞了N10 看到子 agent failed（原因是额度），主线这一轮还没结束。先不算；主线下一次请求也会撞，那时按第一行算 撞的是 claude 的 Opus / Sonnet 单独额度quotaLimits.rateLimitType 是 seven_day_opus / seven_day_sonnet。只把用同一家族模型的终端标成受限

为什么不靠 todo 或“有没有没做完的工具调用”来判断：撞额度只会发生在发请求的时候，也就是一轮还没结束；“这一轮是被额度结束的”本身就说明没做完。正好做完的那一轮已经回到空闲，不会再发请求，也就撞不上。todo、后台子 agent 只拿来写续跑提示，不参与判断。claude 后台请求（起标题、猜下一句）撞额度不会触发 StopFailure，不算（待核对）。

4 · 续跑发什么
Your usage limit has reset. Continue the task you were working on when the limit stopped you, from where you left off. Don’t redo work that is already done.
+ claude，N10 看到有后台子 agent 因为额度停了：
These background agents stopped at the usage limit before they finished:
• Index claude sessions (agent id a1b2c3)
• Weather 10 years ago (agent id d4e5f6)
Check what each one already did, then resume it with SendMessage to its id. If it can’t be resumed, start it again.
+ codex：
If any sub-agents you spawned didn’t finish, check them and spawn them again.
为什么不是一个 “continue”：主线 “continue” 就够，但后台子 agent 断了以后主 agent 只收到一条 failed 通知，不一定会重派；要点名告诉它是哪几个、怎么接回（claude 的子 agent 可以用 SendMessage 按 id 接着做，记录还在）。 为什么不写长上下文：任务的来龙去脉都在 agent 自己的会话里，AgentDeck 知道的不比它多；多写只是多花 token。 顺序：一个终端先发续跑，这一轮做完回到空闲，再按 PL3 发排着的第一条。 claude 自己续的时候：它的续跑不重发你的消息、也不一定重派子 agent。它那一轮做完后，N10 里还有因额度 failed、之后没有重新开的后台子 agent，就补发上面第二段（只发一次）。 提示词是英文，在 Settings › Agents › Resume prompt 里能改；每次续跑只发一次，记进 PL3 卡片的 “Sent”。

贴在白板上（整块白板的所有 agent 终端），框和单个终端可以单独关，规则和 Auto-approve 一样：终端上的设置优先，框上关掉框里的都关。 默认开（已定）：它只做“让被额度打断的那件事接着做完”，不开新活；和 claude 自己的默认一致。不想要就在白板右键关掉。 Keep Mac awake：有终端在等恢复时不让 Mac 睡（沿用 PL3 的默认开）；离恢复超过 12 小时不阻止。 集群里的终端不归它管，见第 8 节。
8 · 和集群 CR8 的分工：一个终端只有一个“续跑的人”
终端谁决定（换家 / 等恢复）谁发 集群里的任务终端集群调度器（CR8），按模板的 onLimit 规则：实现者另一家有额度就换家，没有就等；审查者只等（审查必须换一家）等恢复时调度器调同一个 LimitService 续，提示词带任务编号；换家时原终端标 “handed to …”，Auto-resume 跳过 集群外的 agent 终端只会等恢复（不换家：换家要换会话，上下文丢了）Auto-resume（本插件） claude 自己会续的claudeclaude；AgentDeck 只补发子 agent 那一段

撞额度的识别、按账号归组、错开发送、Keep Mac awake 只写一份，放在主进程（agent-adapters 的 limits 模块，经 contracts 的 LimitService 给界面和集群用）。规则写在 docs/plugins.md 的 PL4 一行和 docs/decisions.md；集群模板里只写 onLimit 选哪种，不另写一套等待和发送。
