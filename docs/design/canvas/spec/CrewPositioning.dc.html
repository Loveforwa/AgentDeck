C9 · 定位：小作坊打不过大公司，AgentDeck 站在哪

2026-10-28 已定（按推荐）

单家的体验（聊天界面、工具调用的样子、云端、手机）我们追不上 Claude 和 Codex 自己的 app，也不去追。原来说能站住的三样是“跨家协作、白板看全局、原生 TUI”。2026-10-27 核对了 14 家：白板和原生 TUI 已经有人做得和我们很像（Nodeterm 也是 React Flow + tmux），跨家并排跑几乎人人都有。还没人做完整的，是让几家 agent 按一套确定的流程把大任务做完：有人守规矩、换家审、额度用完换家、你只在关卡上出现。这就是 M8 集群。

所以三样从“卖点”降成“底座”，卖点收成一件事：几家 agent 一起把大任务可靠地做完，每个 agent 都是原生终端，你随时能接手。

1 · 一句话怎么说
现在（README 首句） Run several coding agents side by side on one whiteboard, one git worktree per branch. 说的是“并排跑、一个分支一个 worktree”。Conductor、Claude Squad、Nodeterm、TermCanvas、Claude Desktop 都能这么说，读者分不出我们。
建议（CR 第一期合进 main 以后再上 README） Hand a big task to Claude Code, Codex and other agents together. AgentDeck splits it, keeps every agent in its own real terminal and worktree on one board, and only stops when it needs you. 说的是“跨家一起做完大任务、只在关卡叫你”，原生终端和白板是让你放心的理由。集群做出来之前，README 先不改，只改内部文档。

3 · 原来说的三样，现在还是只有我们有吗
已经不独有原生 TUI tmux 系（Claude Squad、Agent Deck）和白板系（Nodeterm、TermCanvas、Collaborator）都跑真终端。官方桌面 app 和 T3、Synara、Conductor 不是。 还是要做，它让新功能第一天就能用（claude 的 agent view、/remote-control 在我们的终端里直接能用）。但它是底座，不是卖点。
已经不独有白板看全局 Nodeterm 几乎和我们一样：React Flow + tmux + 钩子状态 + 组绑 worktree + 源代码管理 + agent 开节点的 CLI + iOS。TermCanvas、Collaborator、AgentGrid 也是无限白板。官方给的是列表（agent view、Projects 的 Overview）。 我们能比的是细节：框、排版（N12）、左边栏历史（N11）、网页窗口、⌘J。是做得好不好，不是有没有。
还没人做完整跨家协作 几家并排跑人人都有。按流程协作已经有人在做：TermCanvas 的 Hydra（Lead + 角色 + 关卡文件）、AgentGrid（主 agent + 额度交接）、Nodeterm（组队、互相验）、Synara（换家接着做）。 还没看到的：调度器是一段确定的代码，不靠 Lead agent 自觉。它守 owns 目录、锁接口、换家审、额度用完换家、重启后对账，所有关卡进一个收件箱。这就是 M8，窗口期大概几个月。
4 · 做什么，不做什么（文章里提到的方向逐条过）
做
集群（M8）当头号新方向唯一还没人做完整的。CR1 收件箱先做，它对应 Claude Projects 的 Waiting on you。
原生 TUI 继续当底座不画自己的聊天界面。我们只画 agent 之外的东西：框、收件箱、任务卡、摘要卡、Usage 条。
审美：投在我们自己画的那部分白板、框、收件箱、集群看板照组件库做，暖灰墨黑，颜色只表示状态。不做工具调用和 thinking 的折叠卡片，那是 agent 自己的画面。
卡片：用已有的窗口Session 卡片就是终端窗口和摘要卡，HTML / Artifact 卡片就是网页窗口，任务卡片在 CR5。不另起一套。
和官方的新功能兼容，不重做agent view、agent teams、/remote-control 在我们的终端里能正常用（AH6 实测）。N10 读 claude 子 agent 就是这个思路。
远程：先借各家的，集群整夜跑以后再做“看收件箱、批关卡”见“手机 · 远程”页 R0、R1（M12）。
不做
自己的聊天界面，或把 agent 接成协议再自己画T3、Synara 走的路。代价是模型表现不一定等于原生，各家一改版就要跟。
统一工具集、自己的 harness不替换 agent 自己的读写文件、执行命令这些工具。我们只给 session 级的操作（开终端、派活、交付），形式是 agentdeck 命令行（C7）。
自己的记忆系统长期记忆交给各家（CLAUDE.md、AGENTS.md、auto-memory）。短期记忆就是集群任务表。Agent as Memory 见 C8。
搜索是 agent 自己的能力，最多做成插件；AgentDeck 不做，写一页说明（RM4，R0）。
云端跑 agentCursor、Claude Projects、Codex 云端都有。我们是本机工具，代码不离开你的电脑。
追单家的深度功能Codex Automations、Claude Projects、computer use 这些，用户直接用官方的。
每家都深做适配深做 claude、codex（omp 修好 IS-76）。pi、kimi 走 generic 适配器加命令行进集群（C7），新 agent 靠社区贡献。
