有人主张“Agent as Memory”：人只跟一个主 agent 说话，主 agent 记着进度、开子 session、再回来跟你汇报，因为人的精力有限，来回切 session 很累。我们的出发点一样，但分成三份：进度记在 AgentDeck 的数据里（任务表、你做过的决定），要你拍板的事进收件箱（C4），Lead 负责跟你聊：到哪了、为什么、要不要改方向。Lead 的上下文只是缓存，压缩了、重开了、换一家当 Lead，都能从 AgentDeck 生成的进度摘要接上。

2 · 记忆分两种，AgentDeck 只管短期的
长期：偏好、注意事项短期：进度 例子“组件里不写颜色值”“提交前跑 pnpm check”“我喜欢小提交”T6 审了两轮、T7 在等你批接口、你答过 QA “Same frame” 存在哪各家 agent 自己的：仓库里的 AGENTS.md / CLAUDE.md；claude 的 auto memory（~/.claude/projects/<仓库>/memory/，同一仓库的所有 worktree 共用）；codex 的 memories（默认关）。AgentDeck 的数据（SQLite）：任务表、Decisions（你在收件箱和关卡上做过的决定）、crew notes、还开着的关卡。不往仓库写。 谁写你；auto memory 由 agent 自己写。调度器写状态，你的每个决定自动记下，agent 用 crew note 写发现。 AgentDeck 做什么不另做一套记忆，也不往每个终端注入（那是每轮都要付的 token）。只做两件小事：集群不改仓库里的说明文件；集群里的 Worker、Reviewer、QA 启动时关掉 claude 的 auto memory，免得三个并行的任务把“T4 做到一半”写进你的长期记忆（待你定）。存下来，生成进度摘要（第 3 节）给 Lead；Worker 只拿到自己的任务卡和相关的 Decisions，不拿整张表。 短期变长期汇报里的 Decisions 和 notes，值得一直留的（比如“恢复会话一律在原来的框里”）由你自己抄进 AGENTS.md（Copy as Markdown）。AgentDeck 不自动写你的仓库和 agent 配置。
