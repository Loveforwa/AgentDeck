右侧面板，显示当前工作区的 git 状态，操作方式参照 VS Code 的源代码管理。

结构图
1当前工作区：项目名和工作目录，单击路径复制
2分支按钮：切换或新建分支；下面写“3 ahead of main”

4“Staged Changes”：暂存的更改

6悬停在文件上：暂存（+）、放弃更改（↶）
7“Repository”：这个项目的所有工作目录，单击跳到对应的框；不在白板上的灰显并写“not on board”，单击出现“Add to board”
8“Commits”：最近 20 个，分隔线“On main”以下是 main 上的提交；单击一行复制哈希

文件操作
  • 单击文件：面板内显示它的差异（只读），顶部有“Back”和“Open in editor”。
  • 双击文件：在编辑器中打开。
  • 组标题上的 + / −：全部暂存或全部取消暂存。
  • 放弃更改要确认“Discard changes to oauth.ts? This can’t be undone.”；未跟踪的文件改为“Move notes.md to Trash?”。
  • 没有暂存时按钮写“Commit all n changes”，第一次使用会确认一次。
切换分支前的检查
  • 有未提交的更改：“Switch with changes”（git 允许时才出现）、“Stash and switch”（切回来时提示恢复）、“Cancel”。
  • 有 agent 正在这个目录里运行：额外提示它看到的文件会变。
  • git 拒绝切换：显示 git 的原始错误。
  • “New branch…”从当前提交新建并切换过去。
刷新与边界情况
  • 只在三种时候刷新：切换聚焦的窗口或工作区；agent 一轮结束（钩子通知）；你自己提交、暂存、切换分支之后。
  • 不监听文件变化。在外部编辑器里改了文件，下次聚焦或 agent 一轮结束时更新；右上角有手动刷新按钮。
  • 提交失败（如 pre-commit 钩子不通过）：提交框下方显示命令输出，可以展开。
  • 仓库在合并或变基中：分支旁显示“Merging”，冲突文件排在最上面，按钮变成“Complete merge”。
一个工作区里有多个仓库 例如 shop 文件夹下有 web 和 api 两个仓库

shop 本身不是 git 仓库，但里面的 web、api 各是一个仓库。问你要不要把它们当成一个项目；选“Add separately”就是两个独立项目

勾选这次要改的仓库：勾上的各建一个 worktree，用同一个分支名；没勾的不放进这个工作区，agent 看不到也改不到。比如只改前端，就只勾 web

agent 在父目录 feat-checkout/ 里运行，能同时改 web 和 api

面板按仓库分组，各自显示分支和改动

实现难度
功能难度为什么 只显示这个工作区的改动容易每个 worktree 是独立目录，有自己的 HEAD 和暂存区。git -C <目录> status --porcelain=v2 只返回这个目录的改动，天然隔离，不用我们过滤。 当前分支、被占用的分支容易status 的输出里就有分支和 ahead/behind；哪个分支在哪个目录来自 git worktree list --porcelain。 暂存、提交、切换分支容易直接调 git add / restore / commit / switch，出错就显示 git 的原文。 多个仓库中等上面每条命令按仓库各跑一次，界面分组显示；难点在新建和删除时几个仓库要一起成功或一起回滚。 提交记录中等MVP 只列当前分支和基础分支上的提交，不画任意分支的图。 合并、变基、冲突只做显示显示状态和冲突文件，解决冲突交给编辑器，不自己做合并编辑器。 大仓库注意大仓库 status 可能要几百毫秒，所以只在三个时机刷新、在后台进程里跑、不卡界面；超过 1 秒显示“Refreshing…”。
多仓库规则
  • 识别：添加的文件夹本身不是仓库，但下一层有 2 个及以上 git 仓库时，问一次“Add as one project”还是“Add separately”。只看下一层，不往深处找。
  • 新建工作区：勾选的仓库各建一个 worktree，用同一个分支名，放在同一个父目录下，例如 ~/.agentdeck/worktrees/shop/feat-checkout/web 和 /api。agent 和终端在父目录里运行。没勾的仓库不出现在这个工作区里。
  • 每个仓库的基础分支分别识别（远端默认分支，其次 main，再次 master）。某个仓库建 worktree 失败时，已建好的全部撤销，并显示是哪个仓库、git 的原始错误。
  • 面板：顶部是工作区名和“2 repositories”；下面每个仓库一组，组标题是仓库名和它的分支，组里是它的改动。
  • 提交：提交框在最上面，一条信息会在每个有暂存（没有暂存时是有改动）的仓库里各提交一次；按钮写清“Commit 5 changes in 2 repos”。只想提交一个仓库，单击那一组标题旁的“Commit this repo”。
  • 切换分支：在每组标题的分支上单独切；顶部的“Switch all…”把所有仓库切到同名分支，某个仓库没有这个分支时提示新建。
  • 删除工作区：每个仓库的 worktree 一起删除，规则同 4 · 工作区框。
  • 子模块（submodule）：MVP 只显示为一条“Submodule changed”，不展开。
