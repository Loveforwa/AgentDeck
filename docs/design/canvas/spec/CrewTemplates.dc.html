C5 · 模板、分期、已定

草案

模板只写“形状”：角色、阶段、关卡、规矩。具体拆成哪些任务由总设计每次现拆。模板是一个文件加几份角色提示词，和 skill 一样能放进库里、放进仓库、分享给别人。

1 · 模板文件长什么样
name: Contract-first build description: Plan, lock interfaces, build in parallel, review, merge, accept. roles: lead: { agents: [claude], prompt: roles/lead.md } worker: { agents: [codex, claude], prompt: roles/worker.md, max: 4 } reviewer: { agents: [claude], prompt: roles/reviewer.md, notSameAs: worker } integrator: { agents: [claude], prompt: roles/integrator.md, onlyOnConflict: true } qa: { agents: [codex], prompt: roles/qa.md } stages: - plan: { by: lead, gate: approve-plan } - contracts: { by: lead, lock: [packages/contracts/**] } - build: { flow: [work, check, review, merge], reviewRounds: 2 } - accept: { by: qa, failuresBecome: issues } - report: {} rules: check: pnpm check maxAgents: 3 retry: { times: 2, then: next-agent, finally: ask-human } onUsageLimit: next-agent-or-wait skills: { worker: [agentdeck-plugin] }
放在哪：自带的在 AgentDeck 里；你自己的在库里（<数据目录>/crews/）；仓库里的 .agentdeck/crews/ 只读出来列在 New crew 里，不往仓库写。 角色提示词：模板旁边的 roles/*.md，说这个角色怎么想、怎么交付。任务的具体内容由调度器每次填进去（C3 的第 3 节）。 agents：按顺序写几家，前一家额度用完或失败两次就交给下一家。New crew 对话框里能改。 skills：按名字引用 N9 库里的 skill，按角色带进去。你自己目录里的其余 skill 按角色选 Leave as is / Names only / Turn off，Worker 默认 Names only（K0 第 3 节）。 不是编程语言：只有固定的几种阶段和规矩，调度器认得的才能写。要新形状就加一种阶段，不在模板里写脚本。 第一期不开放模板文件，Contract-first build 写死在代码里；跑顺了再抽成文件（第三期）。
2 · 自带的五种
Contract-first build · 接口先行、分头实现第一期
Lead 拆任务你确认→Lead 定接口、锁住→Workers 分波并行→检查 · 换家审 · 合并→QA 验收→汇报你合回 main
适合：大功能、新模块，能拆成几块各管各的目录。 就是 AgentDeck 自己的开发方式，拿它自己的下一批任务来验。
Migration · 大规模迁移、重构第三期
Lead 先亲手改 1–2 个当样板你看样板→按文件分批，每批一个任务→Workers 照样板改→每批检查、合并
适合：换库、改 API、批量改写。Owns 就是这一批的文件，几乎不冲突，最能并行。 审查可以抽查：每 N 批审一批。
Bug hunt · 疑难 bug 多路排查第三期
Lead 列出几个猜想→每个猜想一个 agent 去查（不合并）→交证据→Lead 判断原因你确认→一个修 · 一个写回归测试
适合：复现难、原因不明。几家模型各查各的，比一个 agent 一条路走到黑快。 排查的 worktree 只用来做实验，不合进集群分支。
Spec to app · 从需求到能用第三期
QA 先写验收用例你确认用例→Lead 拆任务→Workers 做→QA 在白板的网页窗口里逐条跑→不过的变成新任务
适合：从零做一个页面或小应用，“做完”的标准是用例全过。 验收用到 MVP 的网页窗口和 N1 的 MCP（agent 能开、能看网页）。
Design bake-off · 方案比稿第三期
两三家各自独立出方案→互相挑刺→Lead 综合成一份你拍板
适合：架构选型、大设计。不写代码，只出文档。 出完可以直接接 Contract-first build。
你自己的第三期
复制一个自带的模板改：换 agent、改角色提示词、加关卡、改检查命令。存进库里，或者放进仓库给团队用。 以后可以让总设计看完目标后建议用哪个模板，仍然要你点了才开始。
