2026-10-28 按推荐先定，待你确认

两件小事，都不给 AgentDeck 加新的“学习”或“数据库”功能，只把已有的能力接顺。/teach 是一个普通的 skill：放进库里（M11），在一个专门的学习文件夹里跑，课程和进度都是那个文件夹里的文件，课在白板的浏览器窗口里看。数据库 TUI 就是一个跑自定义命令的终端：后台早就支持，白板上缺一个入口；补上 Custom command… 和启动预设，加一个把选中的 SQL 送过去的菜单，再管住 agent 能不能读、能不能往里打字。

COMMANDS 一组是启动预设：存 AgentDeck 的 settings.json（全局一份、每个项目一份），不写进仓库。一项 = 名字 + 命令（或 agent + 第一条消息，比如 claude + /teach）+ Hide from agents。右边写来源。项目设置页里能改名、删除。没有预设时这一组不显示，只剩 Custom command…。
Custom command… 开出来的终端用现有的 custom 适配器（直接执行，不经过 shell，${VAR} 由工具自己展开）。标题栏写命令的第一个词（现有 title.ts）。窗口重开时照现在的规矩：变成 Shell，命令填好不跑。Hide from agents 存在这个窗口上，跟着白板保存。

不用 agent 的 send_to_terminal：它把换行变空格，上面那句 -- 注释会吃掉后面的 WHERE；它还会按回车。
做法怎么定代价 人把 SQL 送进数据库终端做 Send selection to ▸（终端窗口的菜单，CO3；只粘贴、不按回车）要先选中；agent 输出被折行的长 SQL 选出来带硬换行（xterm 的选择行为，待实测） agent 自己往数据库终端里打字不加新工具；Hide from agents 打开时 send_to_terminal、read_terminal 都拒绝，list_terminals 不列它（AH11，M10，和 AH7 放在同一处检查；会动现有 MCP 的默认行为，实现时单独写进 docs/decisions.md）agent 没法替你“在 harlequin 里跑一下”；要它查库走下一行 agent 只读查库不做内置 skill，也不做数据库 MCP。文档给一个示例 skill（db-readonly）：用 hsql --read-only --timeout 30 -P <profile> -c 或 psql 加只读账号，结果加 LIMIT；你自己 Add skill… 放进库真正挡住写入的是数据库的只读账号；--read-only 和 skill 只是省事，agent 有 shell 就能绕过 连接串和密码AgentDeck 不存密码、不做钥匙串。密码放工具自己那里（harlequin ${ENV}、lazysql ${env:}、pgcli 钥匙串、~/.pgpass、rainfrog 钥匙串）；命令里带密码就挡（第 3 节）；list_terminals 返回的命令里遮掉 ://用户:***@（所有终端）.env 里的 DATABASE_URL 照旧会被复制进 worktree（copyIntoWorktrees 默认），agent 也读得到，这是你的仓库约定，AgentDeck 不改
5 · 不做的
学习 不内置 /teach，不替你装、不自动更新它 不做“学习进度”面板，不读、不汇总学习文件夹或你的学习手册 不做学习类集群模板，不写自由模式的学习用法 New terminal 菜单不加专门的 Learn… 项 不把课程转成别的格式（视频转 PPT 归 E2，文档归“文档”页 D0–D2）
数据库 不做 AgentDeck 自己的数据库浏览器、查询编辑器、结果表格 不做数据库 MCP，不做内置的只读查询 skill 不存密码，不接系统钥匙串，不做连接管理器 不自动探测装了哪些数据库工具来生成预设 不给 agent 新的“往终端贴 SQL”工具；不解析 SQL、不判断危险语句（pgcli 自己有） 重开应用不自动重连数据库（保持现在的“填好不跑”）
