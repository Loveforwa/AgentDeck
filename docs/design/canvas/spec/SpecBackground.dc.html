13 · 后台 agent：平时一个小提示，点开只读查看

2026-10-26 定 概念 · 待确认 N10 · IS-85 · DR-61

agent 并行干活时，多半用它自带的子 agent（claude 的 Agent 工具），不走 AgentDeck 的 open_terminals。这些子 agent 跑在主 agent 的进程里，没有自己的终端，原来白板上看不到，N2 的窗口组也就很少出现。现在用钩子和 agent 自己的记录把它们读出来：平时只在主终端底边挂一个小提示，有后台 agent 时才出现；点开是 N2 的同一列侧边栏，选中一个看它的记录，只读。

两种子 agent
怎么开的跑在哪白板上 子终端（N2，已有）主 agent 调 AgentDeck MCP 的 open_terminals每个是一个真终端，有自己的 TUI侧边栏里一行，点开是它的终端，能打字、能批准 后台 agent（N10，新）主 agent 用自带的工具开（claude 的 Agent / Task）在主 agent 的进程里，没有终端主终端底边一个小提示；点开在侧边栏里一行，选中看它的记录，只读

3 · 什么时候显示什么，数据从哪来
发生了什么白板上从哪读（claude） 主 agent 开了一个后台 agent底边右侧出现提示（第一个时）；侧边栏里加一行，写它的任务描述SubagentStart 钩子给 agent_id、agent_type；任务描述在 subagents/agent-<id>.meta.json 的 description 它在跑绿点和已用时间；记录窗口跟着往下走，工具调用写成一行（WebSearch …、Edit …）只读 subagents/agent-<id>.jsonl 的新增部分（和 Usage 读主对话的办法一样） 它做完了这一行变灰打 ✓，写用时和 token；全部做完时提示变灰写 “5 done”SubagentStop 钩子；token 取记录里的 usage 它出错或被打断红点，写 Failed；提示写 “1 failed”，点开看记录最后几行SubagentStop 加记录里最后一条 你给主 agent 发下一条消息全部做完的提示消失；记录留到关掉主终端前，右键菜单 “Background agents…” 还能打开UserPromptSubmit 钩子 前台子 agent（主 agent 等它做完）也列出来，规则一样同上，meta.json 里写的是前台还是后台 重开应用、Restore不保存，从空开始（2026-10-26 实现时定；记录还在 claude 自己的文件里，以后可以在左边栏里看，画板 14）— 面板开着项目框跟着长到装下侧边栏和记录窗口，挤到的框、盖住的窗口挪开；收起时照原样放回。书签、小提示、Usage 条也算进框里（2026-10-26 定）— claude 自己的内部查询不列：每轮会单独发一两个没有 Start、没有类型的 SubagentStop只认见过 SubagentStart 的

本机 claude 2.1.291 实测：有 SubagentStart / SubagentStop 两个钩子；每个子 agent 一份记录 agent-<id>.jsonl，一份 meta.json（agentType、description、是否后台）。钩子照旧只通过 AgentDeck 启动 claude 时的参数带进去，不改你自己的配置。

支持哪些 agent
agent情况 claude先做：钩子和记录文件都有 codex、pi、omp、kimi先调研有没有子 agent、怎么读（DR-61）。读不到的不挂提示，不猜
不做的
不能在后台 agent 里打字、批准或停止它：它没有终端，要改就在主终端里跟主 agent 说。 不把后台 agent 变成真终端；需要能插手的并行任务，点名让 agent 用 open_terminals。 不另做成插件：这是 N2 窗口组的一部分，右键菜单里不加开关。
