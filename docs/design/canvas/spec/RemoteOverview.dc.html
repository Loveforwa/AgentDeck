R0 · 手机和远程：人不在电脑前，也知道谁在等你、能批该批的

2026-10-28 已定（按推荐）

终端都在 AgentDeck 自己的 tmux 里，应用关了窗口也在后台跑，所以“远程”不用搬走任何东西：只要让手机看到收件箱（CR1）、集群进度和汇报，必要时批一下关卡（CR6）。不在手机上重做一个聊天界面：单家 agent 的远程（Claude Remote Control、Codex 的手机端）大公司已经做了，我们只做跨家的那一层。

1 · 三个用途
整夜跑的集群（TC-45）晚上开一个集群走人。凌晨总设计写完任务表停在 Approve plan，没人批就一直停到早上。要：手机响一下，打开看任务表，点 Approve and start。要处理的东西：集群关卡。
出门时看谁在等你开着 5 个 agent 出去吃饭。想知道有没有人卡在批准上、谁出错了，非破坏性的批准顺手点掉。要处理的东西：终端批准、agent 的提问。
早上看汇报通勤路上看 Crew report：几个任务合进去了、谁卡住了、各家用了多少额度。Merge into main 回到电脑前再点。只看，不操作。
2 · 几条路对比（2026-10-27 核对，出处见调研 DR-77）
做法能做什么代价和风险和 AgentDeck 的关系结论 ssh + tmux attach

4 · 分三步做
步做什么不做什么依赖放在哪 RM1 推送Settings › Remote 里填 ntfy 主题或 Bark 地址，Send test；收件箱新来一条、集群跑完、集群停住时推一条（应用在前台时不推）；内容默认只写 “2 need you · Approve plan · history-sidebar”。不写命令和代码；不做邮件（要存密码）。CR1 的 InboxItem；CR8 本来就写了“发手机提醒（方式待定）”M12，可以和 CR8 一起提前做 RM2 手机只读页本机开 remote-server，经 Tailscale 给手机；扫码配对；看收件箱、集群进度、汇报、终端最后 40 行；推送点开直接到这一条。不 attach tmux（不改桌面上窗口的大小）；不开局域网。CR1；集群部分要 CR0、CR5；汇报要 CR7新开 M12 远程，CR1 做完就能开工 RM3 手机上处理打开 “View and act” 后：批集群关卡（Approve plan、Interface change、Stuck 里的 Skip / Reassign）、终端的非破坏性批准、回答 agent 的提问；每次都记进 Approval history，桌面弹一条 Toast。Merge into main、破坏性命令、往终端随便打字：手机上都不行，写 “Do this at your Mac”。RM2；CR6 的关卡M12，CR6 做完之后
5 · 安全规矩（远程能批命令 = 远程能执行命令）
谁能连上 · 只听 127.0.0.1，从外面只能经 tailscale serve 进来；发现这个端口开了 Funnel（公网）就拒绝启动并说明。 · 第一次要在 Mac 上扫码配对：二维码里是一次性配对码，5 分钟过期，用一次作废；换来一个设备令牌（只存哈希），手机上存成 HttpOnly; Secure; SameSite=Strict 的 cookie。 · 还要对上 Tailscale 带来的 Tailscale-User-Login，必须是这台 Mac 自己的登录账号（两道都过才行）。 · 和 MCP 分开：另一个端口、另一个令牌；MCP 的令牌在这里没用，这里的令牌在 MCP 那边也没用。
能做什么 · 三档：Off（默认）/ View only / View and act，每台设备单独定。 · 可以：集群关卡（不含合回 main）、非破坏性批准、点 agent 给的选项、回一句话给问你问题的那个 agent。 · 不行：Merge into main、命中破坏性名单的命令、开 / 关 Auto-approve、开新终端、往没在问你的终端里打字。 · 改状态的请求用 POST，带自定义请求头，别的网站的页面发不出来；每台设备每分钟最多 30 次操作。
看得见、关得掉 · 开着时顶栏有一个 Remote 标记，点开看连着几台设备、最后一次操作，一键 Turn off。 · 每次手机上的操作都记进 Approval history（by remote · iPhone），桌面弹 Toast “Approved from iPhone: pnpm test”。 · Settings › Remote 里能吊销单台设备；吊销后手机页立刻变成 “This device was removed”。 · 推送内容默认不带命令和代码（命令里可能有密钥）；要带得自己打开 Include details。
