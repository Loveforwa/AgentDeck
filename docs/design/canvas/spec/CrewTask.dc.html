2 · 调度规则
情况怎么做 先派哪个波次小的先；同一波里依赖先满足的先，再按编号。一波没全合进去，下一波里依赖已满足的也可以先开（不用死等整波）。 同时开几个在干活的 agent（实现者、审查者、集成者、验收者）不超过 Limits 里的数，也不超过还有额度的 agent 数。空着的总设计不占位。 开一个任务从集群分支现在的位置切出 crew/<name>/T4 和它的 worktree，在里面按角色开终端（带角色的 skill、Auto-approve；环境里有这个终端自己的 AGENTDECK_TERM_KEY，PATH 里有 agentdeck），把任务提示词发进去（见 3）。 怎么算做完只认 agentdeck crew done。agent 回到空闲却没交付：提醒一次 “If you’re done, run agentdeck crew done. If you’re stuck, run agentdeck crew ask.”；再空闲就算等你。 检查交付后调度器自己在任务 worktree 里跑 Check 命令。没过：把输出最后一段发回实现者，任务回 Working。 目录归属交付时看这个任务的 diff：改了 Owns 以外的文件就打回，写清是哪些文件。锁住的接口目录只有批准过的接口改动能改。 审查审查者默认不和实现者同一家。它用 agentdeck crew diff 看改动、能在同一个 worktree 里只读地跑命令，最后 agentdeck crew review 给 approve 或 changes。（第二期）项目里有图时，审查者按图核对这次改动动到的步骤，审查结论里多一节 Flows；验收者（QA）对动到的步骤跑测试覆盖，汇报里列没跑到、没加载的步骤和建议的 TC（“代码理解”页 F2 第 3 节）。 合并调度器把任务分支 --no-ff 合进集群分支，再跑一次检查。冲突才开 Integrator 终端。合并顺序按交付先后，一次一个。 接口改动实现者跑 agentdeck crew contract 写清要改什么、为什么。关卡通过后由总设计改接口、单独合进集群分支，其他在做的任务收到一条提示 “Interfaces changed: …”。 关掉应用、重启集群状态存在 AgentDeck 的数据里，终端在 tmux 里接着跑。重开后先对账：每个 Working 任务的终端还在不在、有没有已经交付。 集群结束验收全过、或者你点 Stop：出汇报（C4），任务 worktree 清掉，分支都留着；集群分支等你合回 main。研究集群先给登记过的产物（Outputs）存快照，再清 worktree（RS5，“研究和竞赛”页 E1 第 5 节）。
3 · 发给实现者的第一条提示词
Worker · codex · T4sent by the crew scheduler
You are a Worker in crew “history-sidebar” (template: Contract-first build).
Your task is T4 “Sidebar list UI”. Read it first: agentdeck crew task

Rules:
- Only change files under packages/ui/panels/history/**.
- packages/contracts/** is locked. If you need a change there, run
agentdeck crew contract <paths> "<why>" and wait.
- Write anything the others should know: agentdeck crew note "<text>"
- When the task’s “Done when” is met and tests pass, run
agentdeck crew done "<summary>". The scheduler runs pnpm check itself.
- If you are stuck: agentdeck crew ask "<question>"
- Every agentdeck command prints JSON; agentdeck crew help lists them.
角色提示词来自模板（C5），任务的具体内容（编号、目录、检查命令）由调度器填进去。 仓库里的 AGENTS.md、CLAUDE.md 照常由 agent 自己读，集群不改它们。 发送方式和 PL3 一样：整段用 bracketed paste 送进输入框，再单独按回车。所以第一条消息不依赖启动参数，IS-76 不挡集群。 Worker 只拿到这几行命令（约 70 token，随对话缓存），没有开新终端的命令，也看不到 Lead 的命令（服务端按角色拒绝，见 C7）。
4 · agent 用的 crew 命令（模板模式；agentdeck 命令行，不进 AgentDeck MCP；自由模式 Lead 的操作见 C6）
命令谁能用做什么 agentdeck crew task [id]所有角色读任务卡：目标、依赖、Owns、Done when、锁住的目录、检查命令。不写 id 就是自己手上的任务。 agentdeck crew planLead、Integrator、QA读整张任务表和每个任务的状态。 agentdeck crew add · update <id>Lead写任务表（长内容从 stdin 读）。开始以后只能加新任务、改还没开始的任务。 agentdeck crew readyLead任务表写完了，交给你确认（关卡）。命令只能“申请”，批准只能你在界面上点。 agentdeck crew done "<summary>"Worker交付。调度器接着跑检查、看目录。 agentdeck crew diff <id>Reviewer、Integrator拿这个任务相对集群分支的 diff。 agentdeck crew review <id> approve|changesReviewerapprove 或 changes，意见（stdin）原样发回实现者。 agentdeck crew note "<text>"所有角色记一条发现（相当于 CONTRACT_NOTES），汇总进汇报，Lead 和后开的任务能读到。 agentdeck crew issue "<title>"所有角色，主要是 QA记一个问题（详情从 stdin）；Lead 把它拆成新任务。 agentdeck crew contract <paths> "<why>"Worker申请改锁住的接口（关卡）。 agentdeck crew ask "<question>" [--option …]所有角色问你一个问题，进收件箱；你的回答原样发回这个终端。 agentdeck session spawn · list · read · send · wait · result · close只有 Lead自由模式（No template，C6）里 Lead 自己开、看、指挥别的 session，完整的操作见 C6 第 3 节。Worker、Reviewer 调用一律拒绝：“Only the Lead can open sessions.”，不会一层套一层。
认身份：调度器开终端时给每个终端一把自己的钥匙（AGENTDECK_TERM_KEY，由 AgentDeck 的密钥和终端 id 算出），命令带着它连回 AgentDeck；服务按钥匙认出是哪个终端、哪个集群、什么角色，只改环境变量里的终端 id 冒充不了别人。能进集群的条件从“接了 AgentDeck MCP”改成“能跑 shell 命令、有回合结束信号”：claude、codex、omp、pi（kimi 等它有钩子和自动批准，先灰掉写 “Needs approval for every command”，见 C7）。
