先写表再跑：Lead 读论文，把要对的数一条条写成 Claim（表或图的编号、页码、数据集、指标、设置、论文里的值、有没有给方差），再估每条要多少 GPU 小时。Plan 关卡里你勾哪些要跑、容差多少；批准后 Claims 锁住，跑完不能回头改目标。 差多少谁算：Ours 来自 Run（AgentDeck 跑评测命令读出来的数，几颗种子就取均值和标准差），Δ 和 Status 由 AgentDeck 按容差算：在容差内 Reproduced，两倍以内 Close，再远 Off；硬件不同的写 Not comparable，没跑的写原因。 差异要写清：为了能跑而改的设置（批大小、卡数、版本、数据来源）由 agent 用 agentdeck crew note --kind deviation 记，汇报里单独一节，和对照表放在一起看。 你库里的 paper-claim-audit、result-to-claim 这类 skill 可以带给审查的角色，查“这个数能不能支撑论文的说法”；AgentDeck 只管数从哪来、差多少。
4 · 复现的环境怎么隔离
代码：每个尝试一个 worktree（crew/<name>/<label>），论文仓库的某个提交 + 为了能跑打的补丁。AgentDeck 本来就这么做。
Python 环境：放在 worktree 里面：.venv（uv / pip）或 .conda（micromamba / conda 的 -p 前缀）。不装进你的全局 Python、不动你的 base 环境；下载缓存共用一份。默认。
容器：仓库自带 Dockerfile、或要系统库时用；放在 Linux 的 SSH 机器上跑。Mac 上的 Docker 用不了 GPU，x86 镜像在 Apple 芯片上要模拟，很慢。
GPU：要 CUDA 的训练和评测作为 Job 放到 SSH 机器（E1 第 3 节），那边同样建在本次 Run 的目录里。
AgentDeck 做什么：不替你建环境（那是 agent 和 skill 的事），只做两件：给研究集群的终端加护栏环境变量（PIP_REQUIRE_VIRTUALENV=1，pip 不能装进全局；conda 的环境目录指到 worktree 里，待核对变量名），以及在每个 Run 上记环境指纹（锁文件哈希、Python、torch、CUDA、GPU 型号）。 为什么不默认容器：大多数论文仓库给的是 requirements.txt 或 environment.yml，不给镜像；Mac 上容器拿不到 GPU；一个容器几 GB。worktree 里的环境够隔离、删 worktree 就删干净。 环境本身也是一个小关卡：Builder 搭好后跑一次冒烟（导入、加载权重、跑 10 个 batch），过了才开始正式的 Run；装不上的包和换掉的版本记成 deviation。
