2026-10-27 定 2026-10-28 补：第 6 节和规则表里标 10-28 的行，草案 PL3 · IS-88 · DR-63

5 小时额度用完了，你还有很多想法要它做。在 agent 终端上开 Prompt queue，先把提示词一条条排进去；这个终端的 agent 碰到额度上限时，插件按 agent 自己记下的恢复时间到点（多等 1 分钟）把第一条发进去，它做完一轮回到空闲再发下一条；又碰到上限就等下一次恢复，发完为止。你不在电脑前也能接着跑。

5 · 规则
情况怎么做 什么时候发第一条这个终端的 agent 碰到额度上限（5 小时或每周），并且到了记录里的恢复时间 + 1 分钟，并且 agent 空闲。
10-28 改（IS-113，PL3 提交前修）：“碰到上限”记下来就不忘（armed），之后哪怕上限被一次成功的请求清掉也照发；按账号算，同一账号别的终端撞了也算（待你确认）；这个终端被打断时先续跑（PL4），续跑那一轮做完再发第一条。 claude 自己续跑（10-28 补，IS-113）claude 2.1.234 起默认在恢复后自己接着做（autoContinueAtUsageLimit）。它在等的时候不往里粘贴：粘进去的话 claude 会发你的提示词、不再续原来的事。等它续的那一轮做完回到空闲再发；它说 stale（Mac 睡过头，要按回车）或 disabled 时交给 PL4。 什么时候发下一条上一条那一轮做完、agent 回到空闲（状态机的 turn-end）。中间你自己打了字，就等你这一轮也做完。 怎么发和批准一样走终端的按键（tmux send-keys）：先把文字送进输入框，再按回车。多行的按 agent 自己的多行写法送。 不发的时候在跑、等你批准、等你回答、终端退出了、你点了 Pause、应用关着、电脑睡着。应用重开后按保存的队列接着等。 恢复时间读不到不猜：书签写 “Limit reached · reset time unknown”，等你点 Send next now。 记录每发一条记下时间和内容（卡片里能看），提示词只存在白板里，不写进 agent 的配置。
