无人值守的 agent 不会停下来问你“能不能跑这个命令”，所以边界不能靠批准，要靠它够不着。I2 里我们自己写过“去掉 gh 登录和推送凭据，这不是沙箱：agent 有 shell 时仍可能读 ~/.ssh”。这一页把它补成真的隔离：每个 Run 一个容器，只挂它自己那个 worktree，只给调模型要的那一个登录，推不出去、看不到你的家目录，网络默认只放行模型和包仓库。现成的三家都是这个路子：Sandcastle（Docker、Podman、Vercel 微虚拟机）、Docker Sandboxes（每个 agent 一台微虚拟机、自带 Docker，2026-01 起 macOS 可用）、Dagger 的 container-use（每个环境一个容器加一条 container-use/<名字> 分支）。

3 · 用哪个容器运行时
运行时隔离代价结论 Docker 兼容的：Docker Desktop、OrbStack、Colima普通容器，共用 Linux 虚拟机的内核；在 Mac 上本来就隔着一层虚拟机最常见，大多数人已经装了默认 Podman同上，不用常驻守护进程命令基本一样支持 Docker Sandboxes每个 agent 一台微虚拟机，自带 Docker，回不到宿主（Docker 2026-01 的说法）要新版 Docker Desktop；挂 worktree、端口怎么映射待核对有就优先用（无人值守） Apple container（macOS 26）每个容器一台轻量虚拟机较新，和 Docker 命令不完全一样，待核对以后再看 都没有—不偷偷退回到直接在 Mac 上跑告诉你装什么（像 gh 那样），无人值守的这一项灰掉

5 · 什么时候用容器
场景容器说明 无人值守的 Run（U1、W0 夜里的计划）必须没有容器运行时就不能开 跑别人 PR 的代码（I2 的 Run this PR’s code）默认用原来写“沙箱第二期”，提前到这里；作者不是成员时只能在容器里跑 集群里的 Worker（C2）可选模板里一项 runtime: container；Lead 留在 Mac 上 你自己开的终端不用照旧在 Mac 上的 tmux 里；想要的话新建菜单里选 Open in container
