完整的文字版（包括所有交互表，中文界面文案的旧版本）：AgentDeck MVP 需求

MVP 要做到的事

在一块白板上同时开多个工作区，每个工作区对应一个仓库的一个分支；在工作区里开 agent 终端和网页窗口；一眼看出哪个 agent 在等你；点进去直接回复；在右侧面板提交和切换分支；终端里的本地链接直接在白板上打开。

本页用到的说法
  • 聚焦：键盘输入会进入的那个窗口，同一时间最多一个；边框变深、带阴影。
  • 选中：用来一起移动或删除的对象，可以多个；只有 1px 深色描边。
  • 散放：不在任何工作区框里的窗口。
  • 视口：白板当前显示在屏幕上的那一块。
名词和关系
名词界面上叫是什么数量关系 白板Board整个应用的主界面，可以无限平移的画布。MVP 只有 1 块 项目Project加入应用的一个本地文件夹，记住路径和几项设置。通常是一个 git 仓库；也可以是包含几个仓库的文件夹（多仓库项目），或没有 git 的普通文件夹（不能建分支）。任意多个 工作区Workspace项目 + 一个工作目录 + 一个分支，在白板上是一个框。目录是新建的 worktree，或者项目主目录（Main folder）。没有 git 的项目只有主目录工作区，没有分支。一个项目多个；主目录工作区每个项目最多 1 个 终端窗口Terminal运行一个命令（agent 或 shell），进程由 tmux 托管，AgentDeck 只负责显示和同步信息。创建时确定工作目录，之后不能改。属于 0 或 1 个工作区 网页窗口Browser显示网页或本地 HTML 文件，不绑定进程，可以在框之间移动。属于 0 或 1 个工作区 右侧面板Source Control显示当前工作区的源代码管理，跟随聚焦的窗口切换。1 个 摘要卡（无文字）终端被拉小后的样子，只显示最后 3 行和状态。每个终端都可以变

一个分支同一时间只能在一个目录里检出（git 的规则），所以一个分支最多对应一个工作区。要让两个 agent 并行改同一个仓库，就开两个工作区，各自一个分支。
