Run 什么时候算数：agent 跑 agentdeck run start，工作区有没提交的改动就拒绝（“Commit your changes first, the run must point at a commit.”），所以每个 Run 都指向一个提交。数据和锁住的文件记哈希；环境记锁文件的哈希和几个关键包的版本。 分数谁算：run done 时 AgentDeck 在这个提交的 worktree 里跑 New crew 里填的打分命令（Lead 写、你在 Plan 里看过、之后锁住），读它输出的数。agent 自己报的数只放在 Agent said 一行作对照，差太多时这一行标出来。这和 C3 的“检查是调度器自己跑的，不信 agent 嘴上说的测试都过了”是同一条规矩。 可疑的数：分数比 baseline 高很多、各折分数散得厉害、OOF 文件行数不对、改动碰了锁住的目录，都在表里标一句（只提示，不拦）。要更严的话，Lead 可以开一个别家的子 session 用你库里的实验审计类 skill 查一遍。 Rerun：在同一个提交上按同一条命令再开一个 Job，结果记成新的 Run，用来看分数稳不稳。 一次实验不是一个 session：一个方向一个 session，里面一行行 Run。session 被压缩、换一家接着做（SE6）时，Runs 都在 AgentDeck 里，不靠对话记着。
3 · GPU 和长时间训练放在哪：Jobs
LOCAL · 第一期这台 MacAgentDeck 自己的 tmux 里开一个隐藏的窗口跑命令，输出写进日志，结束时记下退出码。适合表格类比赛（LightGBM、CatBoost 用 CPU）、小模型、评测、转写（mlx-whisper / whisper.cpp）。Mac 没有 CUDA：要 CUDA 的训练和复现放到 SSH 机器上。
SSH HOST · 第二期你自己的 GPU 机器Settings › Compute 里加一台（用你 ~/.ssh/config 里的名字，免密登录）。AgentDeck 把这次 Run 的提交打包传过去（git archive），在那边的 tmux 里跑，定时看日志和退出码，结束后把声明过的产物拉回 worktree。数据目录在那台机器上配一次。按 GPU 数量排队。断网不影响训练（在远端 tmux 里），恢复后接着看。
COMMAND · 你自己的Kaggle Notebooks、Modal、vast.ai……AgentDeck 不租、不开、不关云机器，也不拿你的云账号。agent 用你装的命令和 skill（如 serverless-modal、vast-gpu）组一条命令，交给 Job 跑；能马上返回的平台再给一条查询命令，AgentDeck 按它看状态。花钱的事永远是你的命令、你的账号。

6 · 新加的命令（agentdeck 命令行，C7 的同一个入口）
命令谁能用做什么 · AgentDeck 守的规矩 run start [--label] · run done <id> [--said 0.85]Lead 和子 session开一行 Run（工作区不干净就拒绝）；done 时 AgentDeck 跑打分命令。只能写自己 session 的 Run run list [--sort cv] · run show <id>Lead（子 session 只看自己的）读表，JSON；Lead 被压缩后靠它找回（和 crew status 一起） job start [--on host] -- <cmd> · job list · job tail · job cancelLead 和子 session马上返回；超过 GPU 预算拒绝；同一台机器按 GPU 数排队（和 session 的上限不同，Job 排队不拒绝） out add <path> [--kind report|table|slides|submission] [--run R4]Lead 和子 session登记产物；路径要在自己的 worktree 或共享目录里 submit ask <run> "<message>"只有 Lead进收件箱等你；只能申请，提交只在界面上点 claim add · claim link（复现，E2）只有 Lead写论文里的目标数；Plan 关卡过后锁住
子 session 的第一条提示词多 4 行（run start · run done · job start · out add，约 80 token），只在开了 Results 或 Jobs 的集群里有；它们照样不能开 session、不能申请提交。
