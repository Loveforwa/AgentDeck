10 · 全局规则

跨组件的规则：删除和撤销、快捷键、不在 MVP 里的功能，以及 MVP 完成时要能走通的验收场景。

删除与撤销
对象结果确认能否 ⌘Z 网页窗口关闭不确认能 已退出的终端关闭不确认能 运行中的终端结束进程并关闭确认不能 工作区框“Remove from board”，或“Also delete the worktree folder”对话框只有前者能 多选工作区一律按“Remove from board”处理有运行中的就确认一次能，进程恢复为已退出 项目只从应用里移除，磁盘不动确认不能

⌘Z 撤销的是白板上的操作：移动、改大小、放大还原、新建和关闭窗口、用“Remove from board”移除的工作区。结束进程、git 操作和删除磁盘上的目录不能撤销。焦点在网页或输入框里时，⌘Z 交给它们。

快捷键

终端聚焦时，所有不带 ⌘ 的按键都交给终端，所以应用自己的快捷键都带 ⌘。Windows 和 Linux 上 ⌘ 换成 Ctrl。

和实施方案相比的调整
  • 终端拉小后显示摘要卡提前到 MVP，否则一屏放不下多个窗口。放下更多窗口靠拖边框改大小，不靠双指捏合缩放白板。
  • 自动生成提交信息放到 v0.2，MVP 里提交信息必须手写。
  • 原型里“把终端拖进框就自动切换目录”改为不能换框（见 5 · 终端窗口）。
  • 终端进程改由 tmux 托管，从 v0.3 提前到 MVP：关掉应用后 agent 继续运行、重开后历史还在、可以在系统终端里接上，都随之进入 MVP。
  • 去掉文件监听：右侧面板只在切换聚焦、agent 一轮结束、你自己操作 git 之后刷新。
  • 产品界面文案统一用英文；需求说明保持中文，引号里的英文是界面上实际显示的文字。
验收场景

MVP 完成时，每一条都要能从头走到尾。

  1. 第一次打开应用，右键 › “Add project…”，选 api-server 文件夹，直接进入新建工作区对话框。
  2. 在对话框里基于 main 新建分支 feat/oauth；框出现，worktree 建好，.env 已复制，pnpm install 在框里的终端中自动运行。
  3. 同一个仓库再建 fix/rate-limit 工作区；两个框里各开一个 claude，同时改代码，互不影响。
  4. 其中一个 claude 请求批准命令：2 秒内它的窗口变橙，框和顶栏显示“1 waiting”；应用在后台时收到系统通知。
  5. 按 ⌘J 跳到那个窗口，直接按 y 批准，状态回到运行中。
  6. 在框里开普通终端运行 pnpm dev，单击输出里的 localhost:3000，网页窗口出现在它右边、同一个框里。
  7. 聚焦 claude，右侧面板显示 feat/oauth 的更改；暂存两个文件，写提交信息，⌘↩ 提交，提交记录里出现这一条。
  8. 在面板里尝试切换到 fix/rate-limit：它显示“in fix/rate-limit”，单击后白板跳到那个框。
  9. 把两个终端的右下角往里拉：变成摘要卡，显示最后 3 行和状态；单击其中一个，恢复原来的大小并聚焦它。
  10. 退出应用再打开：所有框和窗口的位置不变，终端还在运行，历史输出都在。
  11. 在 claude 的标题栏右键 › “Open in system terminal”：系统终端里出现同一个会话，两边输入同步。
  12. 删除 fix/rate-limit 工作区并勾选删除目录：有未提交更改时必须先勾选确认；完成后磁盘上的目录消失，分支还在。
  13. 关掉窗口：claude 继续跑，需要批准时收到系统通知，单击通知窗口回来并跳到它。
  14. 重启电脑后打开应用：弹出“Restore your last session?”，单击“Restore all”，工作区和窗口都在原位，claude 接回原来那个对话，Shell 在原目录打开。
