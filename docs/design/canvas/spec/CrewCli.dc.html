C7 · agentdeck 命令行：crew 命令不进 MCP，只在 Lead 里打开

草案

CR3 原计划把 12 个 crew 工具加进 AgentDeck MCP。改成一个 agentdeck 命令行，agent 在自己的终端里跑：没打开的终端一个 token 也不多付；Worker 拿不到开新 session 的命令，不会一层套一层；pi 这类没有 MCP、但能跑 shell 的 agent 也能进集群。MCP 和命令行背后是主进程里同一份工具实现，现有 11 个 MCP 工具保留，只把常驻的说明缩短。

2 · 谁看得到什么
普通终端 白板上自己开的 claude、codex、omp：照旧带 AgentDeck MCP 的 11 个工具（open_browser、notify、open_terminals…）。 看不到任何 crew 命令；跑 agentdeck crew plan 只会得到 Not in a crew. 只碰自己产物的命令所有 AgentDeck 终端都有（子 session、Worker 也有）：agentdeck doc（打开文档、核对引用、读和回复评论，见“文档”页 D0）、agentdeck flow（verdicts 只认 Verifier，F2）、agentdeck lesson propose / list / search（W1），研究集群里的 run start / run done / job start / out add（E1 第 6 节）。认身份靠终端钥匙；这些命令都不能开终端、不能批准、不能提交、不能合并。开 session、管子 session、跑 crew 流程的命令仍然只给 Lead。 每轮 ~200 token（instructions 缩短之后）
Worker · Reviewer · QA 调度器发的第一条提示词里写了它要用的那几条命令（done、note、ask、contract 或 review）。 服务按角色拒绝 Lead 的命令和 agentdeck session …；MCP 里的 open_terminals、create_workspace、send_to_terminal 对它不列出。 每轮 ~270 token
Lead 模板模式：调度器开的总设计，第一条提示词里带着命令说明。 自由模式（No template，C6）：你在 Skills · MCP 里勾上 crew，或在 claude、omp、pi、kimi 里打 /crew，才把说明装进对话。 只有 Lead 多一套开子 session、管子 session 的 agentdeck session spawn · list · read · send · wait · result · close（spawn 就是 open）；集群本身的是 agentdeck crew status · diff · check · merge · ask · note · done，模板模式的角色命令见 C3 第 4 节。 打开前 0，打开后每轮 ~460
