AgentDeck 在真终端里跑各家 agent，“谁在等你”“会话 id”“用了多少”“替你按允许”都是每家单独接的：有的靠钩子，有的靠扩展、会话文件，有的只能看屏幕。现在这些信息散在代码里，界面上只有点到某个灰掉的菜单项时才看到一句原因。这一页把它们摆在一处：每家一张能力表，写明靠什么做、稳不稳、核对到哪个版本；agent 升级到没核对过的版本时，哪些功能自动关掉、为什么，也在这里说。

菜单、SKILLS 小节、New crew 的下拉里灰掉的原因，和这一页用同一份数据（能力报告），说法一字不差。

1顶上一行：名字、装的版本、上次检查时间、Check again。Check again 只做不花钱的探测：--version、在 --help 里找我们要带的参数、带钩子空启动一次等 SessionStart 再关掉；不发提示词。codex 的 SessionStart 要等第一次输入，这一项写 “Checked at last launch”。检查时按钮写 Checking…。
2左边一组 AGENTS：装了的 agent 按菜单里的顺序列出，名字前面是 agent 身份色的小方块（组件库：身份色只用在区分 agent 的小标记上）。没装的已知 agent 列在最后，灰掉，hint 写 Not installed，点进去只有一句怎么装。
3版本比核对过的新：一行 muted 文字说明，不用黄色（黄色只给“等你”），也不弹框。只有按键、认屏这类“替你按”的功能自动关掉（Off），钩子、扩展、会话文件照常用。Check again 跑过、合格测试的记录更新后，这行消失。
4能力表：一行一项。Support 只有 Yes / Partial / No / Off 四个词，Yes 用 ink，其余用 muted；Check again 失败的那一项写 Failed，用 error 红（这是真的出错）。How 写靠什么做，Note 写原因，原因就是菜单 hint 用的那句。
·Extra launch arguments：原来只能在 settings.json 里改的 agents.<id>.extraArgs 挪到这里，Save 和别的页一起存。

没画的状态：没装（只有一句 “Install Oh My Pi, then reopen this page.”）；检查中；检查失败（失败的行写 Failed 和输出的第一行，例如 “unknown option --plugin-dir”）。

4 · 规则
什么时候怎么做 打开这一页读 agents.report，不跑任何东西；报告在应用启动、检测到 agent 版本变了（二进制的修改时间变了）时由主进程重算。 点 Check again跑 agents.check(agent)：版本、--help 里找参数、带钩子空启动等 SessionStart（10 秒），然后关掉。不发提示词，不花额度，不写 agent 自己的配置。 版本超过合格测试核对到的版本顶上一行 “Newer than checked”；只把 Screen + keys 这类能力改成 Off（Note：Untested on <版本>）；钩子、扩展、会话文件照常。合格测试（A1）跑过并提交记录后恢复。 版本号读不出按没核对处理（同上），不再当作“够新”（DR-60）。 钩子没来（disableAllHooks、信任哈希对不上、扩展加载失败）Status 一行写 Partial · Terminal activity，Note 写原因，例如 “Hooks didn't report at the last launch”；对应终端的状态灯悬停也写这一句（A1）。 颜色这一页只有一个地方用状态色：检查失败的那项写 Failed，用 error 红。其余都是 ink 和 muted；“Newer than checked” 不用黄色，因为它不是在等你。
