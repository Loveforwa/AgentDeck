PL1 · Auto-approve：替你按“允许一次”

插件 · 窗口 / 工作区框

开在一个终端上，或者开在整个工作区框上。开着的时候，agent 请求权限（跑命令、改文件、联网）就直接回“允许一次”，不用你切过去按。只有三种情况照常停下来等你：agent 让你在几个选项里挑一个、破坏性命令、要你打字回答。

替你按的，和照常等你的
agent 在等什么开着时说明 权限请求：跑命令、改文件、联网、调 MCP 工具允许一次只选“Yes”，从不选“Yes, and don’t ask again”，不替你改 agent 自己的权限设置。 破坏性命令（rm -rf、git push --force、git reset --hard…）照常等你名单就是 Settings 里的 approvals.destructivePatterns，和 Approve all 共用。 选择题：agent 列出几个选项让你挑（AskUserQuestion、计划要你选方案）照常等你这是你的决定，不是权限。 要你打字回答（Needs reply）照常等你同上。 批准没生效（2 秒内状态没变）停下来书签临时变成橙色 “Needs you”，终端照常亮橙色等你。

NoPermissionRequest 钩子到 HookServer，decide 回 allow（只这一次，不留规则）。提问和计划确认也走这个钩子，已经单独分出来，不答。 codexYes, proceed (y) / Yes, and don’t ask again… (p / a) / No…同样走 PermissionRequest 钩子回 allow。开关前就在等的，补发 y；永远不发 p、a。 kimi1. Approve once / … / 4. Reject with feedback暂不支持（只能看屏幕，先不做）。菜单里灰掉，写 “Not supported for kimi yet”。 ompAllow tool: … / Approve · Deny扩展先报 PermissionRequest，屏幕出现 Allow tool: 后发 ↑ ↵（先在真终端里核对）。 pi没有确认框（pi 从不问）不用按。书签照常显示，悬停写 “pi never asks for approval”。

contracts 里已经有 setAutoApprove、approval.auto-approved 事件、ApprovalRecord.by = 'auto-approve' 和 history()，现在都是占位实现。每次自动批准写一条记录，Approval history（右键框，或点书签）按时间列出：哪个终端、什么请求、谁批的（你 / Approve all / Auto-approve）。Approve all 还是顶栏上一次性的操作（不设快捷键），规则和这里共用。
