3 · AgentDeck 怎么加、怎么减（只用启动参数，只影响 AgentDeck 开的终端）
agent加：库里的 skill（N9，已做）减：Names only减：Turn off，Keep these 照带还要核对的 claude--plugin-dir <setDir>，显示成 agentdeck-skills:<name>现有的 --settings JSON（已带钩子）里加 skillOverrides: {name: "name-only"}同上，取值 "off"和你自己 settings 里的 skillOverrides 怎么合并；插件里的 skill 不受它管 codex加不进（Not supported for codex）；试本地插件 marketplace（DR-83）没有这一档，按 Turn off 处理并写明-c skills.config=[{path=…,enabled=false},…]几十项时命令行长度和转义 pi每个一个 --skill <文件夹>没有，可用第二期的索引代替--no-skills，再把 Keep these 和库里选中的用 --skill 加回来--no-skills 会不会连仓库里的也关掉（应当关，再按 repo 加回） omp--plugin-dir <setDir>没有--skills=<keep…,库里的…>；或 --no-skills + --plugin-dir--skills 会不会把 setDir 里的也筛掉 kimi--skills-dir <setDir>/skills，加上它自己的目录没有只传 --skills-dir <setDir>/skills（setDir 里只放要留的），不再传它自己的目录没在真 kimi 里核对过（N9 同）
setDir 按内容生成在 AgentDeck 的数据目录里（复制，是一份快照，正在跑的会话不受库里改动影响）；旧的 setDir 要清理（现在不清）。被 agent 拒绝的参数按 IS-73 的启动保底处理：退回不带减法重开，标“降级”。
4 · 一个终端最后带什么：三层，集群角色是一套预设
Settings › Skills全局默认：库里哪些默认开；你目录里的默认 Leave as is
→
Project settings › Skills这个项目：库里带哪些；其余的 Leave as is / Names only / Turn off；Keep these
→
这个终端（N9 的面板）勾选、Your other skills 换一档；存在 TerminalWindowData.skills
→
启动参数prepareLaunch 合并三层 → setDir（加）+ 每家的减法参数 → 适配器
集群开终端时（CR2）按角色套一套终端选择：Lead 带 crew（C7）和模板里的；Worker、Reviewer 带模板里的，其余默认 Names only；Worker 永远不带 crew
↑ 不做的两层：按工作区框（同一项目的几个框就是几个 worktree，要的几乎一样）；按 agent 种类（由第 3 节的支持表决定，界面上写原因）。
