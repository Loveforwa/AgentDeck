用户笔记第 2 条：让多 agent 帮你打 Kaggle、从几个网站收论文新闻日程并辅助读论文、搭论文环境复现代码，视频链接也进同一个流程（取原文、分析、出 PPT）。这些任务的产物不是一条要合回 main 的分支，而是报告、表格、PPT、提交文件；“做完”看的不是检查过没过，而是一个分数或者和论文里的数差多少；几路尝试不合并，而是比；一次训练要跑几个小时。

结论：做法交给 skill，记账交给 AgentDeck，形状最后才做成模板。第一期在自由模式（C6）上加四样记账的东西：实验记录（Runs）、长任务（Jobs）、产物（Outputs）、提交关卡（Submit）。第二期加资料库（Library）和定期跑（Schedule）。模板文件开放（CR9）以后，再出四个研究模板（E3）。

3 · 三层：skill 管做法，AgentDeck 管记账，模板管形状
第三层 · 研究模板
研究第三期 · 等 CR9四个模板文件（E3）：Competition、Literature watch、Paper reproduction、Video to slides。只写形状：角色、阶段、关卡、规矩。要加三种新阶段（explore、fanout、deliver），其余用 C5 已有的。给长任务和整夜跑；任务形状清楚以后才值得写成模板。
第二层 · 集群核心里的记账
研究第一、二期Runs、Jobs、Outputs、Submit（第一期）；Library、Schedule、按条目的进度（第二期）。两种模式都能用，自由模式里也有。这些是“安全和记账”，和 C6 的分法一致：不能交给 Lead 自觉，分数不能让 agent 自己报、提交不能让 agent 自己交、几小时的训练不能让 agent 盯着。这是 AgentDeck 自己要写的代码，第 4 节列出每一样。
第一层 · skill 和各家的工具
现在就有怎么读论文、怎么做特征、怎么用 whisper 转写、怎么出 pptx，都写在 skill 里，放在 N9 / Skill 管理（K0、K1）的库里，按角色带进去。你的库里已经有不少（本会话能看到的名字里有 arxiv、semantic-scholar、research-lit、run-experiment、experiment-queue、vast-gpu、paper-slides、pptx、alphaxiv 等）。搜索、看图、看视频是各家 agent 自己的能力。AgentDeck 不写这些 skill，也不打包 yt-dlp、whisper。只靠这一层就是“自由模式 + skill”：能跑，但分数、提交、长任务、去重没人记账。
回答“做成新模板，还是自由模式加 skill 就够”：先自由模式加 skill，再补第二层的记账，最后才是模板。只有 skill 不够，因为缺的是记账，不是做法；直接做模板太早，因为 CR9 第三期才开放模板文件，而且 Kaggle 每个比赛的形状都不太一样，先在自由模式里跑几次再定。
4 · AgentDeck 要新做的东西（界面 + 底层）
东西界面底层哪些场景期 Runs 实验记录白板上一种新窗口 Results：Runs 页按分数排、最好的加粗、点一行看 Run 卡片（E1 第 1、2 节）；Claims 页给复现用（E2 第 3 节）SQLite 里的 Run：session、分支和提交、命令和配置、种子、数据和环境的指纹、Job、各折分数、产物；分数由 AgentDeck 在这个提交上跑锁住的 score 命令竞赛、复现第一期 Jobs 长任务集群框底部一条 JOBS：在哪跑、跑了多久、最后一行日志；Job 也能开成一个只读终端本机 tmux 或 SSH 机器上的长命令，记日志和退出码；跑完把结果打进开它的 session；排队等 GPU；重启对账竞赛、复现、视频转写第一期本机，第二期 SSH Outputs 产物集群框标题条多一个 Outputs · N；汇报多 Outputs、Runs、Claims、Sources 几节；最后的关卡按模板变成 Accept outputs / Submit登记路径、哈希、出处；集群结束前把产物复制到 <数据目录>/crews/<id>/outputs，先存快照再清任务 worktree（C3 写了结束时清掉任务 worktree）全部第一期 Submit 提交关卡收件箱一条 Submit to Kaggle：哪个 run、CV 多少、格式检查、今天还剩几次AgentDeck 自己执行提交，取回公榜分数；发现绕过关卡的提交时报红竞赛第一期 Library 资料库左边栏多一页 Library（和 History 并排）：论文、新闻、日程、视频，新的加粗，疑似重复能合并；点开在白板上开 PDF 或网页一条一个 Markdown 文件 + SQLite 索引；文件夹默认在数据目录，你主动改了位置才写到别处（你点了才写，AgentDeck 不提交）；agentdeck lib add 写入时按 DOI、arXiv 号、网址、标题指纹去重收论文、复现、视频第二期 Schedule 定期跑集群框 ⋯ › Repeat…：每天 / 每周几点；资料库顶上写上次和下次AgentDeck 开着时到点用同一套设置新开一个集群；错过的下次打开时补一次；额度用完就等收论文第二期 条目进度集群框里一张小表：每个视频 / 来源一行，每一步一格（E2 第 5 节）模板的 fanout 阶段按步骤记状态；自由模式里 Lead 用 crew item 报视频、收论文第二期 需要的工具New crew 里写 Needs kaggle, yt-dlp, ffmpeg · 2 of 3 found，带安装提示模板的 requires；只检查，不替你装全部第一期 不做的搜索（RM4）、租 GPU 和开关云机器、自己的视频模型、自己的 PPT 引擎、替你建 conda 环境、实验平台（MLflow、W&B 有的话以后只读导入）。
“视频转 PPT 的进度”不单独做界面：用通用的条目进度表加 Jobs。“论文和资料库”做成左边栏一页。“实验对照表”是 Results 窗口，竞赛和复现共用一个零件。

6 · 和已有部分的关系
已有的研究和竞赛怎么用它、要它改什么 C6 自由模式 · CR10第一期就建在它上面：方向 = Lead 开的子 session。改一处：开了 Results 或 Jobs 的集群，子 session 的第一条提示词多 4 行 worker 命令（run start · run done · job start · out add），仍然不能开 session、不能申请提交（已定：C6 改为“子 session 不带 crew 和 session 命令”，这 4 行所有 AgentDeck 终端都有）。 C5 模板格式 · CR9四个研究模板用同一种文件；加 explore、fanout、deliver 三种阶段，score、jobs、submit、library、schedule、requires 几条规矩。Bug hunt 的“几路查、不合并”和 Competition 的 explore 是同一种阶段。 C4 汇报 · CR7汇报按模板多几节；最后的关卡从只有 Merge into main 扩成 Merge / Accept outputs / Submit。 S0、S1 Session（SE0–SE6）一个方向是一个 session，一次实验是这个 session 里的一行 Run，不是每次实验开一个 session（太多）。换一家接着做（SE6）时，交接说明带上这个 session 的 Runs 和在跑的 Jobs。 PL4 Auto-resume · PL5 LimitService · CR8训练是 Job，额度用完不影响它；Job 跑完要叫醒的 session 正在等额度时，消息排在续跑后面再发。整夜跑另加 GPU 预算（GPU 小时用完不再开新 Job）。 K0、K1 Skill 管理（SK6 角色预设）研究角色的预设：Lead 带读论文和计划类 skill，Explorer 带实验类，Fetcher 带下载转写类；库里没有就跳过，不替你装。 搜索不做（RM4）资料库只管存和去重，搜什么、用什么搜由各家 agent 和你装的工具（Exa、OpenCLI…）决定。下视频要不要用浏览器的登录态（cookies）每次问你，默认不用（DR-91）。 A0 能力报告（AH0）加两项：image-input、video-input。视频要不要走“截帧给模型看”就按它判断。 D0–D2 文档（M15）报告、笔记、实验文档的编辑体验依赖“文档”页 D0–D2（M15）；在那之前，产物用网页窗口打开（已经能开本地 HTML，PDF 待核对）。 PL1 Auto-approve永远不自动放行 kaggle competitions submit（已定，另登记问题，不改 PL1 已有的结论）。
