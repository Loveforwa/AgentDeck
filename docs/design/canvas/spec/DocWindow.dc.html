D0 · 文档窗口：在白板上和 agent 一起写需求、技术、实现、实验文档

2026-10-28 按推荐先定，待你确认

白板上多一种窗口：文档窗口，和终端、网页窗口并列。它打开的是工作区里的一个 .md 文件，放在写它的 agent 终端旁边。agent 用自己的工具改文件，窗口跟着刷新、标出它改了哪几段；你在窗口里读、改、选中一段写评论，一键把评论发回那个终端，agent 改完逐条回复。文档里的 path:line 能点回源码，代码变了以后窗口会告诉你哪些引用对不上了（D1）。怎么写得像人话、引用够密，靠自带的 agentdeck-docs skill（D2）。

文件就是文档本身：存在仓库里、跟着分支走、和代码一起提交和审。评论、核查结果、“你看过哪一版”这些不属于文档的东西存在 AgentDeck 自己的库里。

放在哪 agent 跑 agentdeck doc open 时放在它的终端右边（同 open_browser 的 nearTerminal，board.ts:190 BoardEvent）；从终端链接打开时放在那个终端右边。 默认 760×600，最小 420×300；在框里时属于这个工作区，可以拖出去。 拉小到摘要卡时只显示标题、引用的状态数和评论数。
1标题栏：文件名（等宽）和所在目录；右边是最近一次谁改的：“Updated by claude · now”（PostToolUse 钩子带着这个路径、时间对得上时），认不出来写 “Changed on disk · now”，你自己保存写 “Saved · now”。不用状态色。

4引用的总数和出问题的数：changed（代码改过，要重看）用 attention，not found 用 error，单击滚到第一处。细节见 D1。

4 · 怎么打开
  • 终端输出里单击 .md 路径（现在是交给编辑器，TerminalWindow.tsx:243-247）：开成文档窗口，放在这个终端右边，连着这个终端。⌥ 单击还是用编辑器。同一个文件已经开着就聚焦它（reuseKey 用文件路径，同网页窗口）。
  • agent 跑 agentdeck doc open <path>：同上，不抢键盘焦点、窗口闪一下（同 board.open-window 的 highlight）。
  • 右键框 › New doc…：选 Requirements、Design、Implementation、Experiment 或 Blank，写文件名（默认 docs/ 下），生成带提纲的空文件；可以顺手选一个终端 “Ask claude to draft it”。
  • 源代码管理面板的改动列表里，.md 文件的右键菜单多一项 Open as doc。
  • 从访达拖入 .md 文件。窗口里路径下拉列出这个工作区的所有 .md，可以直接切换。

  • 文件是唯一的真相。窗口记着读进来那一版的哈希；磁盘变了而你没改过：直接换成新的，滚动位置按标题留住。
  • 你有没保存的修改时磁盘变了：三方合并（读进来的那版、你的、磁盘上的）。改的不是同一段就自动合上，写 “Merged claude’s changes”；同一段才出上面这条黄条。
  • 你保存时用 baseHash，磁盘在这之间又变了就不写，回到上一条。agent 那边：claude 的 Edit 在文件读过后被改会拒绝，codex 的 apply_patch 对不上上下文会失败（各家待核对），所以它也不会盖掉你刚存的。
  • 两个 agent 改同一篇：同一个工作区里不拦，窗口在标题栏写两个名字，提示 “claude and codex both changed this doc in the last minute”。不同工作区各有一份，合并时按 git 处理。集群里文档路径归哪个任务，按 owns 规则管（CR2）。
6 · 文档放哪、谁来写（已定 2026-10-28：A，仓库里的 .md）
A · 仓库里的 .md（已定）B · AgentDeck 自己的库C · 网页窗口里看渲染后的页面 文档本身工作区里的文件，git 管历史、跟着分支走、随代码一起审SQLite 里一份按块存的文档，像 Claude Docs只读：把 .md 渲染成 HTML 放进网页窗口 agent 怎么写用自己的文件工具，零学习；五家都会每次都要走 agentdeck doc 命令，按块 id 改；指令要进上下文同 A，但人不能在窗口里改 评论、核查结果存在 AgentDeck 的库里，按文件路径（每个 worktree 一份）和文档放一起没有 代价评论在别的编辑器里看不到；文件被外面改了评论要重新找位置（按引用的原文找）不在 git 里、不跟分支、PR 里看不到，换工具就带不走没有评论、没有编辑，等于没做
数据目录里的文件（集群汇报 CR7、AgentDeck 生成的报告）也能用文档窗口打开，只读，⋯ 里有 Save to repo…（你点了才写进仓库，AgentDeck 不提交）。不在仓库里的普通 .md 也能开，只是引用一律算 outside。
第一期做文档窗口（Read / Edit、盯文件、自动保存、三方合并、你没看过的改动）；四种打开方式；引用的渲染、悬停看代码、单击用编辑器打开；机械核对（D1 第 2–4 节）；agentdeck doc open · check；自带 agentdeck-docs skill。
第二期做评论和 Send comments、doc comments · reply；Verify claims（另一家 agent 逐句核查）；New doc… 的模板；集群汇报用文档窗口显示（CR7）；符号锚点用 tree-sitter（和“代码理解”页 F0–F2 一起）。
不做多人实时一起编辑（AgentDeck 是本机应用；别人看用 PR 或手机页 RM2）；所见即所得的富文本编辑（会把 markdown 重新排版，git diff 全是噪音，和 agent 的改动打架）；.docx、Google Docs 格式；把评论写进文件里。
