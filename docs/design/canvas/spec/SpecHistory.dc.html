标题：agent 给对话起的标题（claude、codex 会写），没有就用第一条消息的第一行。 状态灯：在白板上开着的会话才有，和终端标题栏一套（绿在跑、黄等你、空心空闲）。没开着的不画灯。 时间：最后活动，“now / 5m / 2h / 3d / 12 Oct”。 悬停：开着的写 “On board”；没开着的出 Resume 和 ⋯（Fork into… ▸ 别的工作区、Copy session id、Reveal file in Finder）。悬停久一点出说明：模型、来源（桌面版 / 编辑器）、开始和最后活动的时间、目录和分支、第一条消息。不写消息数：要读整个会话文件（几 GB），见 DR-62（2026-10-26 实现时改）。 不支持接回的（kimi 新建的会话、文件里没有会话 id 的）Resume 灰掉，悬停写原因。
3 · 怎么分组、怎么排
层规则 第一层 · 项目AgentDeck 里加过的项目，按最近有会话的排；当前项目（顶栏选中的）放最上面。会话的目录不在任何项目里的放到最后的 Other folders；它默认收起，只露标题和会话总数，点一下展开，开着没有记在这台电脑上（2026-10-26 定）。 第二层 · 工作路径项目的主目录（main folder）和每个 worktree 各一行，写分支名，后面是会话数；能折起来。白板上有框的工作路径默认展开，别的默认收起。 第三层 · agentclaude、codex、pi、omp、kimi 各一组（小标题带个数），组之间按最近活动排，没有会话的不显示；每组先显示 5 条，Show N more 展开。 会话按最后活动时间倒序。只列主对话：claude 的子 agent 记录（subagents/）、codex 的子任务不算。 搜索、筛选顶上的搜索框按标题、第一条消息、分支找（搜索时 Other folders 也展开）。没有按 agent 筛选的一栏（2026-10-26 用户去掉了），agent 小标题前一个身份色的小方块、字也用那个颜色来区分。
4 · 数据从哪来
agent会话文件目录、标题从哪看 claude~/.claude/projects/<目录名>/<id>.jsonl每行的 cwd、gitBranch；标题是 summary / 第一条 user 消息 codex~/.codex/sessions/年/月/日/rollout-*.jsonlsession_meta 的 cwd；标题是第一条消息 pi、omp~/.pi、~/.omp 的 sessions 目录session 行的 cwd kimi~/.kimi-code 的会话目录按目录归类；没有 id 的不能接回

和 Usage（PL2）用同一套找文件的代码，只读，不改、不删 agent 的任何文件。第一次打开时扫一遍（只读每个文件的开头和结尾），之后看文件的修改时间增量更新。具体路径和字段实现前逐个 agent 核对（DR-62）。

和右边栏一样的地方
圆角白底一栏，小标题全大写（HISTORY），宽度能拖（240–480），收起后顶栏的按钮还在。 开关、宽度随白板保存，重启后还在。 颜色给状态灯和 agent 的身份色小方块（--agent-*），别处黑白灰。
不做的
不在左边栏里看对话内容（要看就 Resume 开终端）。 不删、不改名会话文件；不改 agent 的配置。 不同步到别的电脑。
