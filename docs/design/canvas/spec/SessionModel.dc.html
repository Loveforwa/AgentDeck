S0 · 以 session 为核心：AgentDeck 自己的 Session，和窗口、tmux、agent 的会话记录分开

2026-10-27 草案 · 待你定

现在白板上“一个终端窗口就是一个 session”只是看起来如此：数据上是窗口、tmux 会话、agent 的会话 id 三样东西靠窗口临时串着，窗口一关就散了。谁开了谁、名字、选的 skill、/clear 之前的对话，都跟着丢。这一页提议加一个 AgentDeck 自己的 Session：它比窗口活得长，比 agent 的会话 id 稳，父子关系、关掉以后再打开、集群任务的几轮、换一家接着做，都记在它上面。

不做对话格式转换：每家仍然跑自己的原生 CLI，session 之间传的是结论（交接说明），不是对话记录。

2 · 加上 Session 以后
Session（AgentDeck 自己的，存在 SQLite） id: SessionId · agent · workspaceId · cwd parentId: SessionId | null origin: user | spawn(tool) | fork | handoff | crew | adopted agentSessions: [{ id, startedAt, reason }] terminalId: TerminalId | null（停了为 null） state: running | stopped | handed-off label · title · 设置（skill、Auto-approve、Usage）
白板窗口TerminalWindowData.session窗口只引用 Session；窗口组（WindowGroupRef）只管停靠和收起，谁算一组看 parentId
终端进程（tmux）TerminalId恢复、Reopen 时换新的，Session 不变
agent 的会话记录一条 Session 下面按先后挂几段：start、/clear、compact、resume、fork
父 SessionLead、fork 的来源、交接的上一家、集群的总设计
集群任务 · CrewTasksessions: SessionId[]一串 session：实现者、每轮审查者、交接后的接班者
历史栏 · 后台 agent · MCP历史栏把 agent 文件和 Session 表合起来（对不上以文件为准）；后台 agent 挂在父 session 的终端上，不算 Session；MCP 按调用者的终端找到它的 Session
→ ← ← 引用 现在跑在哪个进程（可以没有） 按先后排的几段对话 → parentId ← 存一串 SessionId ← 读 服务放在 apps/desktop 的主进程里（它本来就包着 agents.start 写 store、也认得 MCP 的调用者），不新开服务包。服务不知道窗口：窗口和 Session 的对应只由白板保存，模块边界不变。所有开终端的入口（菜单、历史栏、MCP、X6 恢复、集群）都经过 agents.start，漏带 session 时服务兜底新建一条。
3 · 名词
界面上叫类型是什么 sessionSession / SessionId在 AgentDeck 里开过的一条做事的线：一家 agent、一个目录，有父 session 和来历。白板上的终端窗口显示它，左边栏列出它。 （不出现）TerminalId终端进程，也就是 tmux 会话。一条 session 停了就没有进程，恢复、Reopen 时换一个新的。 conversationAgentSessionIdagent 自己的会话记录（claude 的 jsonl、codex 的 rollout……）。一条 session 下面可以有几段：/clear 一次多一段。 background agentBackgroundAgentagent 用自带工具开的子 agent，跑在父 session 的进程里，只读，不算 session。 Hand offorigin: handoff换一家 agent 接着做：开一个子 session，第一条消息是交接说明。不转换对话格式。
4 · 一条 session 的一生
Running有终端进程在跑
→
/clear · compact同一条 session，多一段对话
→
Stopped关掉窗口、进程退出、电脑重启
→
Reopen开回同一条：名字、label、skill、设置、父子都在
→
Runningagent 用 resume 接上
Fork into…开一条新的 session，origin 是 fork，指向原来的
Hand off to ▸ codex开一条子 session（另一家），原来的标成 Handed off
Lead 开子 sessionMCP / CLI / 集群派活：origin spawn 或 crew
下面三种都会开出新的 session 关窗口时照样问 “Stop and close”，进程照样停；变化只是 AgentDeck 不再忘掉这条 session。关窗口只收起、进程接着在后台跑（像 Claude 的 agent view）这期不做，以后可以加一个 “Send to background”。
5 · 父子关系从哪来
怎么开的origin谁写进去 你从菜单、⌘T 开的user白板。没有父 session。 agent 开的spawn · open_terminal / open_terminals / create_workspace / cliMCP 和 agentdeck 命令行（C7）按调用者的终端找到它的 Session，当作父。 Fork into…fork左边栏、标题栏菜单。父是被 fork 的那条（AgentDeck 没记过的就只记 agent 会话 id）。 Hand off to ▸handoff标题栏菜单、集群 CR8 换家。父是上一家。 集群派活crew · 集群 · 任务 · 角色调度器（CR2）。父是集群的总设计。 历史栏 Resume 一条 AgentDeck 没记过的adopted左边栏。普通终端里开过的、Claude 桌面版里开的，第一次在白板上 Resume 时收进来。
后台 agent（claude 的 Task / Agent、codex 的子 thread）跑在父 session 的进程里，不是 Session；界面上画在同一棵树里，只读。层数不限，界面只画两层。Worker 能不能再开子 session 由第 3、4 点定。
