5 · 终端窗口

运行一个命令的终端，例如 claude、codex 或你的 shell。终端本身是标准终端，不加额外的输入框或按钮；它的用处来自和外部的连接：所在的工作区决定目录和右侧面板，输出里的链接和文件路径可以点，它的状态会变成提醒。

进程由 tmux 托管，不归 AgentDeck 管：关掉 AgentDeck，agent 照样在后台运行，重新打开就接上；你也可以在自己的 iTerm 或系统终端里接上同一个会话。白板上只为看得见的终端打开显示。

新建与输入
  • 右键白板或框 › “New terminal ▸” 选 agent 或“Shell”。在框里新建时目录是工作区目录；散放时是 ~。
  • ⌘N 用默认 agent 新建：放在聚焦窗口所在的工作区、它的右边；没有聚焦时散放在视口中心。默认 560×360。
  • 聚焦时，除了带 ⌘ 的组合，所有按键都交给终端，包括 Esc、⌃C、Tab、方向键和空格。
  • ⌘V 粘贴，多行作为一次粘贴发送。从访达拖入文件：输入带引号的路径。
  • 在内容区拖选文字，⌘C 复制；所以移动窗口只能拖标题栏。
窗口操作
  • 改大小时，松手后才把新的行列数告诉程序，避免拖动中反复重绘。变成摘要卡时不改程序的行列数，恢复时它的画面不会乱。
  • 双击标题栏、放大按钮或 ⌘⇧↩：占满视口（不盖住右侧面板和顶栏）；再做一次还原。
  • 滚动：已聚焦且光标在窗口上时滚动终端历史；否则平移白板。
  • 其他网址用系统浏览器打开。文件路径（如 src/auth/oauth.ts:44）在设置里选的编辑器中打开到那一行。
  • 右键标题栏：“Rename”“Copy folder path”“Clear”“Restart”“Open in another workspace ▸”“Open in system terminal”“Close”。
  • “Open in system terminal”：打开你设置的终端 App 并接上同一个 tmux 会话，两边的输入和输出同步。
为什么终端不能换框

程序启动后，它的工作目录就固定了，外部改不了。如果允许把运行中的终端拖进别的框，界面上它属于新框，实际上还在旧目录里改文件，右侧面板显示的 git 状态就对不上。所以终端在哪个框里创建，就一直属于那个框。

带着对话换框（Fork conversation）
  • 拖进别的框，或右键标题栏 › “Open in another workspace ▸”，都给两个选项：“New conversation”空白开始；“Fork conversation”把当前对话复制成一个新会话，在新框的目录里接着聊。原终端不受影响。
  • 靠 agent 自己的命令实现：claude 用 claude --resume <id> --fork-session，codex 用 codex fork <id>。不支持的 agent 和 Shell 不显示这个按钮，弹窗里写“gemini can’t fork a conversation”。
  • 会话 id：AgentDeck 启动 claude 时自己传 --session-id，所以一直知道；codex 从它的 notify 事件里读。拿不到 id 时同样不显示 Fork。
  • 带过去的只是对话，不是文件。原目录里没提交的改动不会跟过去，弹窗里多一行“3 uncommitted changes stay in feat/rate-limit”。新会话第一次输入前，在输入框上方提示一次“Now in api-server · feat/oauth”。
  • 待验证：claude 的会话记录按目录存放，fork 到另一个目录时可能需要先把记录复制到新目录对应的位置。M1 先用真实的 claude 和 codex 各试一次再定做法。
边界情况
  • 命令找不到：内容区显示“Command not found: claude”，按钮“Open Settings”“Use Shell instead”。
  • 没有找到 tmux：第一次新建终端时提示，并改用随应用打包的 tmux。
  • tmux 服务意外退出：所有终端显示“Session ended”，顶栏出现“Restart all”。
  • AgentDeck 自己用一个单独的 tmux 实例和配置，关掉 tmux 的快捷键前缀，不会和 agent 的按键冲突，也不影响你自己的 tmux。
  • 重新启动时，支持续聊的 agent 多一项“Resume conversation”：用记下的会话 id 接回原来那个对话（claude --resume <id>、codex resume <id>），见 9 · 保存与重启。
