C2 · 白板上的集群：集群框、任务看板、每个任务一个 worktree

草案

集群在项目框里占一块：顶上一条写清它在哪一步、几个在跑、几个等你；左边是任务看板；右边是正在做的任务，每个任务一个 worktree 小框，里面是实现者的终端，审的时候审查者的终端也开在同一个框里。做完合进去的任务收成一排小标签，白板不会越摊越大。

卡片：编号、标题、负责的目录、谁在做（agent 身份色的小方块）、状态点（绿在跑、黄等你、红出错）。等你的那张卡片多一行说等什么。 看板列：Waiting（依赖没做完）、Ready（能做，等空位）、Working、Review、Merged。卡住的任务（失败两次、等你批准改接口）留在原列，卡片标黄，收件箱里有对应的一条。 Table · Board：也能切成表格看，就是任务表本身（编号、依赖、目录、完成标准、分波），你可以直接改；改了未开始的任务立刻生效，改正在做的要先 Pause task。 Reassign…：换一家 agent 接着做（同一个 worktree，新 agent 先读任务和 diff）。
3 · 摆放和样子的规则
情况怎么做 集群框放在哪项目框里，和普通 worktree 框并列；一个项目可以同时有几个集群。集群框整体能拖、能折叠成只剩标题条。 任务框就是普通的 worktree 框（MVP v1 的工作区框），标题前多一个任务编号；终端窗口标题写角色和任务：Worker · codex · T4。 合进去以后任务框收成一个标签，终端退出，worktree 保留到集群结束（点标签只读打开）；集群结束时一起清掉，分支留着。 颜色照全局规则：状态点只用绿黄红；agent 身份色只用在小方块上；集群框本身是墨黑描边，不用彩色。 缩小看全局缩到很小时集群框只画标题条和一行“3 running · 1 needs you · 3 of 8 merged”。
