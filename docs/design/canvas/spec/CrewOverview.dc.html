C0 · Agent 集群：按模板组一队 agent，做一个人盯不过来的复杂任务

2026-10-27 草案 · 待你定

做一个大功能、一次大迁移、一个查不出原因的 bug：一个 agent 做不完，自己开一堆窗口又盯不过来。选一个集群模板，写一句目标，AgentDeck 按模板组一队 agent：总设计拆任务、定接口，几个实现者在各自的 worktree 里并行做，换一家模型来审，合进集群分支，最后验收、出汇报。排活、开窗口、跑检查、守规矩、等额度由 AgentDeck 里一段确定的代码负责，不靠某个 agent 自觉；你只在关卡上出现。

这就是 AgentDeck 自己的开发方式（MVP 任务表、contracts 先冻结、每条线只改自己的目录、集成负责人合并、TC 用例验收），做成产品。

1 · 名词
界面上叫中文是什么 Crew集群按一个模板、为一个目标组起来的一队 agent。一次运行就是一个集群，在白板上是一个集群框（C2），在一个项目里，有自己的集群分支。 Crew template集群模板集群的形状：有哪些角色、分几个阶段、在哪停下来叫你、守哪些规矩。存成文件，能复用、能分享（C5）。 Role角色总设计（Lead）、实现者（Worker）、审查者（Reviewer）、集成者（Integrator）、验收者（QA）。每个角色写明用哪家 agent、带哪些 skill 和 MCP、角色提示词。 Plan · Task任务表 · 任务总设计拆出来的任务表，每个任务有编号、依赖、负责的目录、完成标准、分在第几波。存成数据，不藏在某个 agent 的对话里。 Gate关卡流程里停下来等你的地方：确认任务表、批准改接口、任务失败两次、合并回主分支（C4）。 Scheduler调度器AgentDeck 里的代码，不是 agent。派任务、开 worktree 和终端、把任务发进去、跑检查、拦越界改动、等额度恢复、记录、叫你（C3）。 Crew branch集群分支crew/<name>，从你选的分支切出来；每个任务在 crew/<name>/T3 的 worktree 里做，做完合进集群分支。集群分支合回 main 永远由你来。

3 · 谁做什么
你选模板、写目标、定分工和上限。在关卡上做决定：任务表行不行、接口能不能改、卡住的任务怎么办。最后看汇报、把集群分支合回 main。其余时间不用盯着。
agent想和做：拆任务、定接口、写代码、审 diff、解决合并冲突、跑验收。通过 AgentDeck 的 MCP 和调度器打交道：领任务、交付、报问题、申请改接口、叫你（C3）。不负责排活，也不负责记进度。
AgentDeck 调度器派活：依赖满足的任务给空着、有额度的 agent，在对应 worktree 里按角色开终端。守规矩：自己跑检查、拦越界改动、锁接口、限制同时开几个。记录和恢复：任务状态存在 AgentDeck 里，额度用完等恢复，重启接着跑。只在关卡上叫你。
4 · 和“让 claude 自己当总指挥、开几个 codex”比
一个 agent 当总指挥Agent 集群 进度记在哪它的对话里；几个小时后上下文满了、压缩一次就忘了谁做到哪任务表是 AgentDeck 里的数据，谁也忘不了，白板上一眼看到 断了怎么办额度用完、它卡住、应用重启，整队都停调度器等额度恢复接着派，重启接着跑；一个任务卡住不影响别的 规矩谁守“只改自己的目录”“改接口先停下”靠它自觉调度器检查每次交付的 diff，越界就打回，接口目录锁着 能用几家它会开谁就开谁，额度全压在一家每个角色选哪家，claude 用完了按模板交给 codex 接着做 你怎么看去问它集群框、任务看板、收件箱、汇报
