2 · 项目

应用记住的一个本地文件夹（界面上叫 Project），通常是 git 仓库，也可以是没有 git 的普通文件夹。项目本身不在白板上显示，它通过工作区出现。添加项目有固定的入口：右键菜单和顶栏的“Projects ▾”菜单，加好后直接进入新建工作区。

右键添加项目

右键空白处 › “Add project…”

系统的选文件夹窗口，选 api-server

直接进入新建工作区，项目已经选好

框出现在右键的位置（后面同 4 · 工作区框）

从顶栏的 Projects 菜单

“Projects ▾”列出所有项目；每个项目可以直接新建工作区，或打开它的主目录

对话框出现在视口中心，项目已经选好

添加没有 git 的文件夹 不建分支，直接用这个文件夹

选了一个普通文件夹 notes，不弹“要不要初始化”

新建工作区只剩“Main folder”，没有分支那一行

框的标题只有项目名和路径，不显示分支；终端、网页窗口照常开

SOURCE CONTROL notes isn’t a Git repository. Initialize one to track changes, commit, and create workspaces on new branches. Initialize Repository

右侧面板显示“Initialize Repository”；不点也完全能用

项目记住的设置（Settings › Projects）　没有 git 的项目只有名称、路径、初始化命令三项
名称 · Name默认是文件夹名，可以改。 路径 · Path仓库根目录；没有 git 时就是选的文件夹。 默认基础分支 · Base branch新建工作区时默认从这里分出。自动识别：远端默认分支，其次 main，再次 master。 worktree 位置 · Worktree location默认 ~/.agentdeck/worktrees/<项目名>/，放在仓库外面。 复制的文件 · Copy into worktrees新建 worktree 时复制过去，默认 .env、.env.local。 初始化命令 · Setup command可选，例如 pnpm install。新建 worktree 后自动在框里开一个普通终端运行它。
规则
  • 添加项目的入口：右键空白处 › “Add project…”；顶栏“Projects ▾” › “Add project…”；新建工作区对话框里项目下拉的最后一项“Add project…”。三处都打开同一个选文件夹窗口。
  • 添加后直接进入新建工作区对话框，项目已选好；可以在里面改选“Main folder”。
  • 顶栏“Projects ▾”：最近用过的在前；每个项目下有“New workspace…”和“Open main folder”（已在白板上时改为“Go to main folder”）；最后是“Add project…”和“Manage projects…”（打开 Settings › Projects）。
  • 选的是仓库里的子文件夹时，自动改用仓库根目录，并在提示里写明用的路径。
  • 选的文件夹本身不是仓库、但下一层有多个 git 仓库：可以作为一个多仓库项目添加，见 8 · 源代码管理面板。
  • 选的文件夹不在任何 git 仓库里、下一层也没有仓库：直接按普通文件夹添加，在“Projects ▾”和 Settings 里标“No Git”。它只有一个工作区，就是这个文件夹本身（Main folder）；没有 worktree，没有分支，也没有提交和切换分支。
  • 没有 git 的项目随时可以在源代码管理面板点“Initialize Repository”（相当于 git init），之后就是普通 git 项目：已有的工作区变成主目录工作区，可以开始新建 worktree 和分支。应用从不自动初始化。
  • 别的程序在这个文件夹里执行了 git init：下一次刷新 git（聚焦、agent 一轮结束）时自动发现，按上一条处理。
  • 移除项目：Settings › Projects › “Remove”。白板上它的工作区一起从白板移除；磁盘上的任何文件都不删除。
  • 仓库文件夹被移动或删除：项目标记为“Folder not found”，提供“Locate…”和“Remove”。
