虚线框里是比 PL3 新加的。Run all day 关着时卡片就是 PL3 原来的样子（只有提示词一列，额度恢复后发）。When 的几种：Now、After previous、At 时间、Every day / Weekdays at、After usage limit（就是 PL3 原来那种）。书签和 Prompt queue、Auto-resume 的合成一个：Run · 3 of 7、Run · 3 of 7 · checking、… · fixing (try 2)、Paused · resumes 1:10pm、Run paused · AgentDeck was closed、✓ Run done · 6 of 7。
Skill 是“怎么做”，队列是“做什么、什么时候做”。一条可以只写提示词，也可以选一个 skill（这个终端能用的，由 Skill 管理 K0、K1 决定能用哪些）。AgentDeck 用各家自己的写法调用：claude /name、codex $name、pi /skill:name（omp、kimi 待核对），不把 SKILL.md 正文贴进去。队列里用到的 skill 在开始前并进这个终端的选择。 Done when 是一条命令，agent 回到空闲以后由 AgentDeck 在这个终端的目录里跑，不是 agent 自己说过了就算。没写就只看空闲。失败把最后 40 行和一句固定提示送回去，最多 2 次。 Context：Fresh 时先发各家的清空命令（claude /clear、codex /new……），算同一个 Session 的新一段（S0）。一天的进度记在 AgentDeck 的队列里，不靠 agent 的上下文，清掉不丢。 Max time、If stuck：到点先发一句“收尾：提交能用的、说清剩下什么”，再等 10 分钟算卡住；Skip 就跳到下一条，Stop 就停下进收件箱。 Keep going until done：只给 claude、codex，替你发 /goal。默认关：判断做完靠 Done when 已经够，/goal 每轮多一次小模型判断。 无人值守：Start run 时 Auto-approve 关着，会提示 “The agent will stop at the first permission prompt and wait for you.” 批准规则照 PL1，不因为在跑一整天就放宽。

Usage limitWait and resume: Auto-resume (PL4) finishes this turn, then AgentDeck runs the check. Hand off to codex: SE6 opens a child session with the handoff note; the rest of the queue moves to it.
一个终端只有一个“派活的人”：Day run 开着时，Prompt queue 的发送规则并进同一个 QueueService；额度的识别、归组、错开仍然只在 LimitService 里（PL5）；选 Wait 时 owner 是 auto-resume，它续完这一轮再由 QueueService 跑检查；选 Hand off 时 owner 是 run，Auto-resume 不插手。集群里的终端不能开 Day run（归 CR8 调度器）。
为什么由 AgentDeck 跑检查：agent 说“做完了”不一定对；检查是确定的，换哪家都一样，不花 token。和集群“检查必跑”是同一个执行器。 为什么失败只回 2 次：再多就是同一个错来回改，花额度。卡住的交给 If stuck 和报告，由你明天看。 Reflect after trouble：只在检查重试过或卡住时发一次固定提示（“如果挡住你的是这个项目下次还会碰到的，用 agentdeck lesson propose 提一条；没有就回 no lesson”），平时不发，不多花。 重开应用：只对账、不自动发。上一条是 running 的进收件箱 “Day run paused”，你点 Continue run 后先跑那一条的检查，过了直接下一条。 定时：只在应用开着时生效，错过的写 Missed、不补跑（和 claude 的 /loop 一样）；终端忙着时等这一轮结束。
