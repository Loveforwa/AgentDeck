U1 · 全自动处理 issue：借 Sandcastle，打了标签的夜里自己做完，早上一起看

2026-10-31 提议，待你确认

Sandcastle（github.com/mattpocock/sandcastle，npm 包 @ai-hero/sandcastle，MIT，TypeScript）是一个库：run() 把一个 agent 放进 Docker、Podman 或 Vercel 微虚拟机里，挂一个 git worktree，用非交互模式一轮轮跑到完成信号，提交合回分支。它自带的模板只处理打了 Sandcastle 标签的 issue（用 gh issue list 取），有一条条做、做完一条审一条、先规划再并行、并行加逐分支审查四种。你要的就是这个：挑好的 issue 交出去，夜里自己做完，不用每个都开一个终端盯。AgentDeck 在它外面补四样它没有的：任务面板和报告（U0、W2）、换一家审、撞额度和卡住的规则、对外发言的一道关。规矩拆成两半：容器里面全自动；对外的话攒成一批，早上你看一眼一次点。

2 · 四种排法（照 Sandcastle 的模板，做成 Run 的模板）
模板怎么跑适合在 AgentDeck 里 One by one
simple-loop一个容器，按顺序一条条做，做完一条接下一条小修小补、文档、标签清理；互相有关联的一个 Run，计划是一串条目（W0 的 Plan） One by one, reviewed
sequential-reviewer每做完一条，另一家审一遍再做下一条怕错的、要人信得过的同上，每条多一个审查步 Plan, then in parallel
parallel-planner先规划能并行的，分到几个分支同时做，最后合一批互不相干的 bug一个 Planner + N 个实现 Run Plan, parallel, reviewed
parallel-planner-with-review同上，每个分支合之前先审默认推荐上面的流程图就是这一种

这四种和集群（C5）的模板是同一个东西的两种跑法：集群里 Worker 是终端，这里是后台 Run。所以模板文件格式共用，多一个字段 surface: card。

3 · 什么自动、什么还要你点
动作默认自己的仓库 （项目设置）为什么 在容器里改代码、提交、跑测试自动自动只动容器和它自己的分支 合进暂存分支 afk/<日期>自动（预演干净才合）自动本地分支，不碰 main，不对外 推送 afk/* 分支到你的远端早上一次点自动只有你一个人维护的仓库，推自己的分支不算对外发言 开 Draft PR草稿进收件箱检查和审查都过了就自动开Draft 不会被合；你仍然要看 在 issue 下评论、问复现草稿进收件箱，整批 Post同左以你的名义说话，给别人看的 关 issue不单独关；PR 里写 Closes #n，合并时由 GitHub 关同左Sandcastle 的 simple-loop 让 agent 拿令牌自己关；我们不把 gh 令牌放进容器 合进 main永远你点永远你点最后一道关，手机上也不行（R0）

“自己的仓库”这一档只在仓库的 owner 是你、并且你在 Project settings 里打开时才有；别人的仓库、开源项目照 I0–I2 的规矩。Auto-approve 对容器里的 agent 没有意义（它本来就不问），关在容器里就是这一档的安全边界，见 U2。

5 · 和 Sandcastle 本身怎么相处：三条路
做法怎么做代价结论 A · 兼容：跑你仓库里的 .sandcastle/仓库里有 .sandcastle/main.mts 时，项目框菜单多一项 Run Sandcastle：作为一个 Run 起，读 .sandcastle/logs/ 显示进度，它开的分支和 worktree 认成卡片只能看，进度、额度、审查都是它自己的；它的 .env 里有 agent 令牌，我们不碰先做，便宜 B · 当引擎：主进程里用 @ai-hero/sandcastle 的 run()我们的 RunService 调它：容器供应、worktree 分支策略、完成信号、会话 resume 都用它的；外面套我们的计划、规则、面板、报告它还在 0.x，接口会变；它管不到 tmux 和我们的状态灯；要在主进程里多一个依赖先做一次试验（调研记录一条），再定 C · 自己写RunService 自己起容器、跑非交互模式、收结果重写它已经做好的那部分（容器、分支、resume、日志）B 的试验不过再选

B 值得试的原因：它和我们同一套技术（TypeScript、Node），供应商能换（Docker、Podman、Vercel、不用沙箱），claude、codex、pi 的 resume 已经接好，正好是 U0 的 Take over 要的东西。
