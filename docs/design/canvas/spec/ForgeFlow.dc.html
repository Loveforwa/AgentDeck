I0 · 开源项目的 issue 和 PR：主流程、谁做什么、对外发言只在你点的时候

2026-10-28 按推荐先定，待你确认

你维护或参与一个几百个 open issue 的项目：每天的分拣、自己 PR 的 review 和 CI 来回、审别人的 PR，都可以交给几个 agent 并行做。AgentDeck 不是云上的机器人，它在你的 Mac 上、用你的 gh / glab 登录，所以 agent 写的每一句对外的话都是“以你的名义”。规矩只有一条：agent 只起草，AgentDeck 把草稿放进收件箱，你看过全文点 Post，才由 AgentDeck 发出去。一个 issue 就是一个 worktree 加一个 session，修复可以是单个终端，也可以开集群（自由模式或模板）。

这一页讲流程和规矩；白板和面板长什么样见 I1；收件箱、发言对话框、审别人的 PR、防注入见 I2。任务是 M17 的 FG0–FG13。黄色虚线框是要你点的地方。

2 · 谁做什么

你

选哪些 issue 分拣、哪些开工（或者开 Start the next one automatically 让它按分数接着开）。在收件箱看每一条要发出去的话，改、丢、或点 Post。决定什么时候跑别人的代码、什么时候合并。你的身份发的每一句话都经过你。

agent

读 issue 和代码、判断标签和重复、起草提问。在自己的 worktree 里修、提交、跑检查；读 review 意见和 CI 日志接着改。审别人的 PR：读 diff、在你允许后跑起来看、写审查草稿。只能用 agentdeck forge … 写草稿；拿不到你的 gh 登录和推送凭据。

AgentDeck

用你的 gh / glab 同步、算分、排队、开 worktree 和终端、盯 CI 和 review 线程。把 issue / PR 的文字清洗、包起来再交给 agent，标出作者是谁。你点了以后推送、发评论、开 PR、提交 review、合并；发前重新核对，只发一次，记进 Decisions。不收 webhook、不在云上跑；AgentDeck 关着就不做事。

5 · 做什么、不做什么

做

GitHub（github.com、GHE）和 GitLab（gitlab.com、自建），都通过你已登录的 gh / glab。 同步 open 的 issue 和 PR；本地全文搜索找重复；代码算分排优先级（能看为什么）。 分拣草稿；Work on it 开 worktree 和 session；修复用单个终端或集群两种模式。 开 PR、review 线程交给 agent、CI 失败跟进、审别人的 PR、合并：全部经收件箱或对话框你点。 白板上 issue 框挂 #编号和 PR 状态灯，面板里看这个工作区的 PR。

不做

不当机器人：不收 webhook、不监听别人 @ 谁、不在云上跑、不用 bot 账号。 不自动发任何东西：没有自动回复、自动打标签、自动合并；Auto-approve 永远不碰。 不让 agent 拿你的写令牌；不自动关 issue；不改别人写的正文；不删评论。 不管 Discussions、Projects 看板、Milestones、Releases、Wiki。不做 Bitbucket、Gitea。 不同步你 GitHub 的全部通知，只看加进 AgentDeck 的项目。 第一期不做：跑 PR 的沙箱、手机上发、令牌登录、可调的算分权重。
