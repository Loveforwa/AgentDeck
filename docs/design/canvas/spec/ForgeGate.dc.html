从 issue / PR 开的终端手里有什么

没有你的 gh / glab 登录：GH_CONFIG_DIR 指向空目录，去掉 GH_TOKEN、GITHUB_TOKEN、GITLAB_TOKEN…（实测 gh 2.91.0 有效）。 推不出去：credential.helper 置空、remote 的 pushurl 指向 agentdeck-blocked://、去掉 SSH_AUTH_SOCK；fetch 由 AgentDeck 做。 claude：deny GitHub / GitLab MCP 的写工具和 gh pr comment 一类命令。 有：agentdeck forge show · search · next · triage · comment · reply · review · pr，全部只写草稿，只读这个项目的仓库。 只用环境变量，不改你的任何配置文件。普通终端不受影响。

你点了以后（AgentDeck 主进程）

重新拉一次目标的状态，对不上就再问你。 查令牌、本机路径、别的仓库的内容。 用你平时的 git 凭据推送，用你的 gh / glab 发评论、开 PR、提交 review、合并（永远不带 --admin）。 锁住草稿、只发一次、记进 Decisions。 AgentDeck 不存令牌：没装或没登录 gh / glab 时，只告诉你在终端里跑什么。
风险对策还剩什么 issue 里藏着指令（HTML 注释、零宽字符、明写 “ignore previous instructions”）清洗、包进 untrusted、标作者；agent 拿不到写权限；所有发言你看全文再点明写的指令还在，agent 可能照做本地的事（读文件、跑命令）：各家 agent 的命令批准照常，从 issue 开的终端 Auto-approve 默认关 以你的身份乱发言、把私有内容贴出去（toxic agent flow）agent 只能写草稿；forge 命令只读本项目仓库；发前查别的仓库的路径和本机路径你没细看就点了 Post；用户自己给 agent 配的 GitHub MCP（带写令牌）挡不住，只能在 Work on it 里提示 agent 绕过去推代码去掉 credential helper、pushurl、SSH agent不是沙箱：agent 有 shell 时仍可能直接读 ~/.ssh 的私钥。文档照实写 跑别人 PR 的代码（postinstall、测试脚本、dev server 插件）只读开始；Run this PR’s code 你点；运行环境去掉令牌类变量点了以后和你自己 checkout 一样危险；容器 / 沙箱第二期调研 CI 日志里带出密钥交给 agent 前把令牌类字符串换成 [redacted]没被认出来的私有格式
