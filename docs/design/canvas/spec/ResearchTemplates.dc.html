E3 · 四个研究模板（C5 格式草稿）和 New crew 里的研究设置

2026-10-28 按推荐先定，待你确认· 研究第三期

按 C5 的模板格式写的四个草稿：Competition、Literature watch、Paper reproduction、Video to slides。它们要等 CR9 开放模板文件才能用；在那之前，同样的事在自由模式里做，New crew 的 No template 多三块可选设置（第 3 节）。C5 说模板“不是编程语言，只有固定的几种阶段和规矩，要新形状就加一种阶段”，所以这里列出要加的阶段和规矩（第 1 节），其余照用 C5 已有的。

1 · 要加的阶段、步骤、关卡和规矩
名字种类是什么调度器做什么谁用 explore阶段从一个基准（baseline 或环境）分出几路，每路一个 session，按同一个分数比；默认不合并，几轮后留下最好的几路开 worktree 和 session；每轮结束把 Runs 表交给 Lead 决定 keep / drop / new；keep 之外的停掉；mergeBest 时只合最好的那路Competition、Paper reproduction；C5 的 Bug hunt 也可以改用它 fanout阶段按一张清单（来源、视频、论文）每项开一个 session，每项走同样几步；产物进资料库或 Outputs按清单派活、限并发；每项每步记状态（条目进度表）；一项失败不影响别的Literature watch、Video to slides deliver阶段最后一步：列出必须有的产物和最后一道关检查产物在不在、复制快照、出汇报；关卡 accept-outputs、merge 或 none四个都用；Design bake-off 也该用 run · score · verifyflow 里的步骤run：开 Job 跑长命令；score：用锁住的打分命令算分；verify：换一家核对事实并记来源run 由调度器等（不叫 agent）；score 由调度器跑；verify 只记 agent 交的结果按需 approve-claims · submit · accept-outputs关卡approve-claims 是 Approve plan 的一种（看 Claims 表）；submit 每次提交都问；accept-outputs 是研究类的最后一道只能申请，批准在界面上复现、竞赛、全部 score · jobs · submit · library · schedule · requires · media · env · tolerance规矩打分命令和方向；Job 能去哪、同时几个、GPU 预算；提交到哪、每天几次；资料库文件夹；定期跑；要装的工具；视频的规矩（先字幕、cookies 要问）；环境护栏；复现容差都是调度器认得的固定字段，不写脚本见下面四个
2 · 四个模板
Competition · Kaggle 这类竞赛研究第三期
Lead 读规则、数据、指标，列方向和预算你确认→Lead 写划分和打分，锁住→baseline→explore × 3 方向 · 3 轮→融合→每次 Submit 你点→Accept
name: Competition description: Baseline first, explore directions in parallel, compare on one locked score, submit only when you say. requires: tools: [kaggle] setup: Accept the competition rules on kaggle.com first. roles: lead: { agents: [claude], prompt: roles/lead.md } explorer: { agents: [codex, claude], prompt: roles/explorer.md, max: 3 } reviewer: { agents: [claude], prompt: roles/reviewer.md, notSameAs: explorer } stages: - plan: { by: lead, gate: approve-plan } # directions, budget - contracts: { by: lead, lock: [cv/**, score.py, data/**] } - baseline: { by: lead, flow: [work, run, score] } - explore: { by: explorer, from: baseline, flow: [work, run, score], rounds: 3, keep: 2, review: suspicious } - blend: { by: lead, flow: [work, run, score], optional: true } - deliver: { outputs: [report, runs, submissions], gate: accept-outputs } rules: score: { cmd: "python score.py --oof {oof}", better: higher } jobs: { on: [local, gpu1], atOnce: 1, budget: 12h } submit: { to: kaggle, competition: "{slug}", perDay: 5, gate: always } maxAgents: 3 onUsageLimit: next-agent-or-wait skills: { explorer: [run-experiment] } # only if it's in your library
review: suspicious：只有被标出来的 Run（分数跳得太多、各折散得厉害）才开别家的审查；其余不审，省 token。
Literature watch · 收论文、新闻、日程，辅助读研究第三期
fanout · 一个来源一个 session→lib add（AgentDeck 去重）→Lead 排序写摘要→reader 读前 3 篇、记笔记→资料库 · 今日摘要
name: Literature watch description: Collect papers, news and events from your sources, dedupe them, write a digest, and read the best few. requires: note: Searching uses each agent's own tools (Exa, OpenCLI, ...). inputs: topics: "agent harness, long-running coding agents" sources: [arxiv:cs.SE, arxiv:cs.AI, hf-papers, openreview:ICLR, hn, "rss:https://...", "site:linux.do via opencli"] roles: lead: { agents: [claude], prompt: roles/lead.md } collector: { agents: [codex, claude], prompt: roles/collector.md, max: 3, worktree: none, autoApprove: off } reader: { agents: [claude], prompt: roles/reader.md } stages: - fanout: { by: collector, over: sources, steps: [fetch, add] } - digest: { by: lead } # rank by topics - fanout: { by: reader, over: top-3, steps: [read, note] } - deliver: { outputs: [digest], gate: none } rules: library: { folder: default, dedupe: [doi, arxiv, url, title] } schedule: { every: day, at: "07:00", missed: once } maxAgents: 3
collector 读的是外面的网页：Auto-approve 默认关，抓回来的内容当数据（提示词里写明），不当指令。
Paper reproduction · 搭环境、复现、对数研究第三期
Lead 写 Claims 和预算你勾要跑的→builder 搭环境、冒烟→explore · 一个 Claim 一路→auditor 写差异→Accept（补丁可合回）
name: Paper reproduction description: Turn the paper's numbers into a table, build an isolated environment, rerun, and report every gap. requires: tools: [git, uv or conda] gpu: from the plan inputs: { paper: "arXiv:2601.04321", code: "https://github.com/..." } roles: lead: { agents: [claude], prompt: roles/lead.md } builder: { agents: [codex, claude], prompt: roles/builder.md } runner: { agents: [codex], prompt: roles/runner.md, max: 2 } auditor: { agents: [claude], prompt: roles/auditor.md, notSameAs: runner } stages: - plan: { by: lead, gate: approve-claims } # claims, tolerance, budget - env: { by: builder, isolate: worktree-env, flow: [work, run] } - explore: { by: runner, over: claims, flow: [run, score], seeds: 3 } - audit: { by: auditor } # deviations, odd numbers - deliver: { outputs: [report, claims, patches], gate: accept-outputs, merge: optional } rules: score: { cmd: "{eval command from the plan}", parse: json } tolerance: { relative: 1%, orPaperStd: 2 } jobs: { on: [gpu1], atOnce: 1, budget: 24h } env: { pipRequireVirtualenv: true }
没有官方代码的论文（要从头实现）不在这个模板里，用自由模式。
Video to slides · 视频取原文、分析、核对、出 PPT研究第三期
fanout · 一个视频一个 session→Lead 写带时间点的大纲→checker 上网核对→Lead 出 PPT→Accept
name: Video to slides description: Get the words out of each video, analyze and fact-check them, and turn them into a deck. requires: tools: [yt-dlp, ffmpeg, whisper] # mlx-whisper or whisper.cpp optional: [an agent with video input, for a visual pass] inputs: { videos: [url, url], audience: "reading group", slides: 15 } roles: lead: { agents: [claude], prompt: roles/lead.md } fetcher: { agents: [codex], prompt: roles/fetcher.md, worktree: shared } viewer: { agents: [kimi], prompt: roles/viewer.md, optional: true } checker: { agents: [codex, claude], prompt: roles/checker.md, notSameAs: lead } stages: - fanout: { by: fetcher, over: videos, steps: [info, words, frames] } # whisper runs as a job - outline: { by: lead } # every point cites [mm:ss] - verify: { by: checker, flow: [verify] } - slides: { by: lead } - deliver: { outputs: [deck, transcripts, outline, checks], gate: accept-outputs } rules: media: { subtitlesFirst: true, cookies: ask-each-time } jobs: { on: [local] }
viewer 只在 AH0 报告里有 video-input 的 agent 能选；没有就跳过这一步，只靠字幕和关键帧。

三块都是可选的，不填就是 C6 原来的自由模式。虚线框是这次加的。 Results：填了打分命令就打开 Runs 和 Results 窗口；Lock 那一行把划分和打分脚本加进 Locked paths，改它们要进收件箱等你。复现时这里填评测命令，Lead 在 Plan 里补 Claims。 Compute：打开 Jobs。This Mac 默认勾上；SSH 机器在 Settings › Compute 里加（研究第二期）。GPU budget 和 Stop after 分开：一个管 GPU 小时，一个管 agent 跑多久。 Submit：填了比赛名才有提交关卡；检查 kaggle 命令在不在、登没登录（只检查，不读你的密钥）。“每次都问”不能关。 子 session：打开 Results 或 Compute 后，Lead 开的子 session 第一条提示词多 4 行命令（run start · run done · job start · out add），见 E1 第 6 节。 Literature watch 和视频在第一期也能用 No template 做（Lead 开子 session、各自用自己的搜索和工具），只是没有资料库去重和条目进度；这两样在研究第二期。
4 · 研究角色的预设（SK6 的补充）
角色默认 agent带哪类 skill（你库里有才带，没有就跳过）Auto-approve命令 Lead claude读论文、查文献、做计划、出 PPT 类按 New crewcrew · session · run · job · out · submit ask · claim · lib Explorer · Runner codex → claude跑实验、排队、远程 GPU 类开（破坏性的照样停）run · job · out Builder codex环境、依赖类开run · job · out Collector · Fetcher codex搜索、抓取、下载转写类（arxiv、exa、yt-dlp……）关（读外面的内容）lib add · job · out · crew item Reviewer · Auditor · Checker claude（和被审的不同家）实验审计、论断核对类关crew note · out add Viewer kimi（可选）—关out add
AgentDeck 不带第三方的研究 skill、不替你装；模板里写的 skill 名字在你库里找不到时，New crew 里那一行写 “Not in your library · skipped”。所有角色你的其余 skill 照 K0 第 3 节默认 Names only。
