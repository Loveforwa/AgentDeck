启动后的样子

已经实现的基础功能

白板和窗口

  • 一整块可平移、⌘ + 滚轮缩放的白板，点阵背景；⌘0 / ⌘1 缩放到 100% / 显示全部
  • 窗口外框：拖标题栏移动、拖边和角改大小、放大还原、关闭、聚焦描边、层级
  • 右键菜单：New terminal ▸（列出已安装的 agent）、New browser、New workspace…、Add project…
  • 顶栏：白板名、“n running · n waiting”、Projects ▾、在等你的按钮
  • 布局改动后半秒自动保存，重开应用原样恢复
  • 终端拉小到 320×200 以下变摘要卡（最后 3 行和状态），单击恢复

终端（tmux 托管）

  • 所有终端跑在 AgentDeck 自己的 tmux 实例里，关掉或退出应用后继续运行，重开自动接回，历史输出都在
  • 只为视口里的终端接上显示，移出就断开
  • 按键直通：不带 ⌘ 的按键全部交给终端；Shift+Enter、多行粘贴、拖入文件路径
  • 进程退出显示 Exited / Error 和 Restart；命令找不到有提示
  • 输出里的 localhost 地址和“文件:行号”可以点
  • agent 用登录 shell 的环境启动（拿得到 PATH 和代理变量），claude 在 tmux 里保持真彩色

项目、工作区和 Git

  • 添加项目（自动用仓库根目录、识别基础分支），项目可以是一个仓库、多个仓库或没有 git 的文件夹
  • 新建工作区：新 worktree + 新分支或已有分支，或主目录工作区；复制 .env；自动运行初始化命令；失败回滚
  • 工作区框：标题是“项目 · 分支”，拖标题带走里面的窗口；框里新开的终端在工作区目录
  • 删除工作区：只从白板移除，或连目录一起删；有未提交的改动要再确认
  • 右侧源代码管理面板跟随聚焦的窗口：树形更改、暂存 / 取消暂存、提交（⌘↩）、切换分支（被占用的灰显）、stash 往返、提交记录
  • Git 不监听文件，只在切换聚焦、agent 一轮结束、自己操作之后刷新

agent 状态和提醒

  • claude、codex 的状态来自它们自己的钩子（启动时临时注入，不改你的配置），其他程序看输出活动
  • 标题栏状态点和文字：Running · 4m、Needs approval、Needs reply、Idle、Exited、Error
  • 在等你的窗口：橙色边框、框标题和顶栏显示“1 waiting”，⌘J 依次跳过去
  • 应用在后台时：系统通知和程序坞角标

网页窗口

  • 在白板上打开网页，地址栏、后退、刷新、在系统浏览器打开
  • 单击终端里的 localhost 链接，网页窗口出现在终端旁边、同一个框里；同一地址已开着就聚焦它
  • 本地页面能嵌进来（主进程改响应头），服务端写的登录 cookie 能用；服务没起来时显示出错页和 Retry

工程基础

  • pnpm check：类型检查、代码规范、界面不许写颜色、15 条模块边界规则、所有测试
  • 所有服务都有假实现，各条线可以单独开发和演示
  • contracts 0.1.3：模块之间唯一的约定，并行开发期间只加不改
  • 演示和截图模式：AGENTDECK_DEMO=1、AGENTDECK_SCREENSHOT=<路径>

已知问题

apps/desktop/ASSEMBLY_NOTES.md，都不会让程序崩

  1. tmux-host：变量重名导致终端进程一启动就崩，组装时在构建配置里绕过了，根子没改
  2. tmux-host：打包后默认的 tmux.conf 路径不对，应用现在总是显式传路径
  3. workspace-service：没有“worktree 放哪”的选项，开发模式下借一个假的主目录
  4. 白板：第二次 start() 在白板加载完之前就返回
  5. 白板：新建终端菜单里有用不了的 custom，按 agent id 而不是名字显示
  6. agent-adapters：claude 停在信任提示时状态显示 Idle，应该算在等你
  7. 源代码管理面板：没有聚焦任何窗口时也显示“This window isn’t in a workspace.”
  8. agent-adapters：重开应用后状态都显示“Idle · now”，开始时间没接上
  9. 终端窗口：连着建两个终端时第二个可能误显示“Previous session ended”

还没处理的

  • 线 1 的 13 条接口意见还没整理成 contracts 0.1.4（关闭确认要知道进程在不在跑、⌘K 清历史、拖入文件的路径、打开外部链接等）。
  • 线 2–5 还没把 contracts 0.1.3 的新字段用进各自的代码（白板仍按 type 写特例，网页窗口仍用本地的 reloadToken 等）。
  • 没有 Settings 界面：设置存在 settings.json，点 Settings 用系统程序打开它。
  • 右下角有 React Flow 的水印，可以关掉。
  • 面板的 Repository 区列出了开发期间留下的十几个已合并分支，可以清理。

明天验货

按顺序试，大约 15 分钟。

  1. 启动
    cd /Users/liu/2026/agenduck && pnpm dev

    开发数据在 .agentdeck-dev/，不碰你真实的 ~/.agentdeck。上次的演示终端还在 dev 的 tmux 里，会直接接回。

  2. 让 claude 真的跑起来
    在 claude 窗口里选 “Yes, I trust this folder”

    这一步会写进你的 ~/.claude.json，所以我没替你点。之后发一句话，看标题栏从 Idle 变 Running 再回到 Idle。

  3. 看批准提醒
    让 claude 运行一个需要批准的命令（例如 “run ls in a new shell”）

    应该 2 秒内变橙，框和顶栏出现“1 waiting”；切到别的应用会收到系统通知。按 1 批准。

  4. 新建一个工作区
    右键 › New workspace…，基于 main 新建一个分支

    框出现，里面开的终端在新 worktree 里；右侧面板显示这个分支。用完可以右键框删除，选连目录一起删。

  5. 网页窗口
    在 Shell 里运行 python3 -m http.server 8765，点输出里的地址

    网页窗口出现在终端右边、同一个框里。

  6. 摘要卡和快捷键
    把终端右下角往里拉到很小；试 ⌘J、⌘B、⌘0、⌘1

    变摘要卡，单击恢复；快捷键在网页窗口里也要有效。

  7. 退出再打开
    ⌘Q，再 pnpm dev

    框和窗口位置不变，终端输出都在。

  8. 清理开发数据（可选）
    tmux -L agentdeck-desktop-dev kill-server && rm -rf .agentdeck-dev

    先退出应用再执行。
